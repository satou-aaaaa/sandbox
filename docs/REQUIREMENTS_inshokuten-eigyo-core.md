# 要件定義書 — 飲食店営業許可モジュール

version: 0.1 / 2026-09 作成
対象: kensetsu-kyoka-toolkit の拡張（許認可自動化コアのアドオンとしての実装）
前提となるコア設計: `docs/DESIGN_kobutsu-core.md`

## 0. 本書の位置づけ

本書は、一般消費者向けの需要が特に大きい「飲食店営業許可」（食品衛生法に
基づく営業許可）を対象とした要件定義書である。コアの設計原則・アーキテク
チャは `docs/DESIGN_kobutsu-core.md` を参照。開発環境構築・コーディング
規約・Git運用は既存の `docs/DEVELOPMENT_GUIDE.md` を適用する。

有効期間が自治体・業種により5〜8年と幅を持つ点は、在留資格モジュール
（`docs/REQUIREMENTS_gijinkoku-core.md`）が実証した「可変期間型」リマインド
パターンに近い構造を持つ。ただし在留資格が「満了日そのものを入力として
受け取る」方式であったのに対し、本モジュールは「許可年月日＋自治体ごとに
異なる有効期間年数」から満了日を**計算する**方式である点が異なる
（`docs/DESIGN_inshokuten-eigyo-core.md` 4.3節で詳述）。

## 1. プロジェクト概要

### 1.1 背景

飲食店営業許可（食品衛生法に基づく営業許可）は、既存4モジュール（古物商・
産廃収集運搬・民泊・技人国ビザ）と異なり、開業希望者の絶対数が非常に
多く、行政書士業務の中でも一般消費者（個人での独立開業・小規模飲食店
経営者）からの依頼が多い分野である。令和3年（2021年）6月1日施行の食品
衛生法改正により、営業許可業種が34業種から32業種に再編され、従来の
「喫茶店営業」等が「飲食店営業」に統合されたほか、手洗い設備の構造基準
（ひねる水栓の禁止等）が明確化された。また同改正により、原則すべての
食品等事業者にHACCPに沿った衛生管理の実施が制度化されたが、**これは
許可取得後の継続的な衛生管理義務であり、営業許可そのものの取得要件では
ない**点に注意が必要である（この区別を誤ると、許可要件判定にHACCP実施
計画の有無を誤って組み込んでしまうリスクがあるため、本書で明確に切り
分ける）。

許可の有効期間は自治体・業種により5年〜8年と幅があり、かつ同一自治体内
でも施設の堅牢性・設備の耐久性等の立入検査結果によって個別に年数が
決定される（例: 東京都の飲食店営業は6年、他の自治体では5年・7年・8年等
の設定がある）。この「許可を受けてみないと有効期間が確定しない」という
性質は、建設業許可・産廃収集運搬業許可の「5年固定」とも、技人国ビザの
「入力として満了日を直接受け取る」方式とも異なる、第三の可変期間パターン
である。

### 1.2 目的

1. 施設基準（厨房設備・換気・給排水・手洗い設備等）および人的要件
   （食品衛生責任者の設置）の該当性を判定する
2. 営業許可申請書の記載内容サマリー、および施設図面等の添付書類
   チェックリストをdocxで生成する
3. 許可取得後、自治体ごとに異なる有効期間（5〜8年）を踏まえた更新
   リマインドを、コアのリマインドエンジンに登録する

### 1.3 重要な制約

- **HACCPに沿った衛生管理は許可要件ではなく継続義務**: 厚生労働省の
  整理によれば、HACCPに沿った衛生管理（大規模事業者向けの本格実施、
  小規模事業者向けの「HACCPの考え方を取り入れた衛生管理」）は、営業
  許可の交付要件そのものには含まれない、許可取得後に事業者が継続的に
  実施すべき義務である。本モジュールの要件判定エンジン（4.1節）は
  施設基準・人的要件のみを判定対象とし、HACCP実施状況を判定項目に
  含めない。ただし、許可取得後に必要となる継続義務であることを、
  生成書類・レポートの注記で必ず案内する（FR-I1.5・FR-I2.4）
- **有効期間は許可時の立入検査で個別に決定される**: 有効期間の年数
  （5〜8年）は自治体の条例・要綱に加え、当該施設の立入検査結果
  （施設の堅牢性・設備の耐久性等）によって個別に決定されるため、
  申請前の時点では正確な年数を予測できない。本モジュールのリマインド
  機能は、許可証交付後に許可証記載の有効期間年数を入力してもらう
  ことを前提とする（許可前の見込み年数からの自動計算は行わない。
  `docs/REQUIREMENTS_gijinkoku-core.md` 1.3節の在留期間が「更新の
  たびに変わりうる」性質と同様、事後入力を前提とする設計とする）
- **風俗営業関連の許可・届出は対象外**: 深夜（午前0時以降）に酒類を
  提供する飲食店営業を行う場合に必要な「深夜酒類提供飲食店営業届出」
  （風俗営業等の規制及び業務の適正化等に関する法律に基づく、公安委員会
  ＝警察署への届出）、および風俗営業許可（同法に基づく許可）は、
  食品衛生法に基づく飲食店営業許可とは所管・根拠法が異なるため、本
  モジュールの対象外とする（4.6節）。深夜酒類提供飲食店営業を行う
  事業者から依頼を受けた場合、本モジュールは飲食店営業許可部分のみを
  支援し、届出部分は対象外である旨を利用者に明示すること
- 既存原則（`docs/DESIGN_kobutsu-core.md` 1章）を継承し、本システムが
  どれだけ自動化されても、最終的な申請書類の内容確認・保健所への
  提出は依頼者本人または登録行政書士が行うことが必須であり、これを
  省略・代替する機能は実装しない

## 2. 用語集

| 用語 | 説明 |
|---|---|
| 飲食店営業許可 | 食品衛生法に基づき、食品を調理し、又は設備を設けて客に飲食させる営業を行う際に必要な、保健所（都道府県・保健所設置市等）が交付する許可 |
| 食品衛生責任者 | 食品衛生法施行条例等に基づき、営業施設ごとに設置が義務付けられる者。調理師・製菓衛生師・栄養士等の資格保有者、または都道府県知事等が行う講習会の受講修了者が就任できる |
| HACCPに沿った衛生管理 | 令和3年6月1日施行の食品衛生法改正により制度化された、原則すべての食品等事業者に義務付けられる衛生管理の実施方法。大規模事業者向けの本格的な実施と、小規模事業者向けの「HACCPの考え方を取り入れた衛生管理」（業界団体作成の手引書に基づく簡略版）に区分される。許可要件ではなく許可取得後の継続義務 |
| 施設基準 | 食品衛生法施行条例等に定める、営業施設の構造・設備に関する基準（2槽以上のシンク、耐水性の床壁材、適切な換気・照度、洗浄後の手指の再汚染を防止できる構造の手洗い設備等） |
| 事前相談 | 施設の工事着工前に、設計図面等を保健所に持参して行う相談。着工後の是正を避けるため、着工前の相談が強く推奨される |
| 実地検査 | 施設完成後、保健所職員が営業者立会いのもとで施設基準への適合を確認する検査。許可証交付の前提となる |
| 深夜酒類提供飲食店営業届出 | 風俗営業等の規制及び業務の適正化等に関する法律に基づき、深夜に酒類を提供する飲食店営業を行う場合に警察署（公安委員会）へ行う届出。飲食店営業許可（食品衛生法）とは別の手続きであり、本モジュールの対象外 |

## 3. 想定利用者・利用シーン

既存モジュールと同じ利用形態（発注者本人が行政書士登録完了後、CLI/
スクリプト操作で使用）。想定シーンとして、個人での独立開業を目指す
依頼者、または小規模飲食店の複数店舗展開を行う事業者から、新規出店に
伴う営業許可手続きの依頼を受け、①事前相談前の施設基準・食品衛生責任者
要件の判定→②施設完成後の申請に向けた書類サマリー・添付書類チェック
リストの生成→③許可証交付後の有効期間満了リマインドの登録、という
流れを想定する。加えて、複数店舗を展開する依頼者について、店舗ごとに
自治体・有効期間年数が異なりうる複数の `LicenseEntry` を1クライアントに
登録できることを想定する（既存の `upsertClientLicense` の枠組みをその
まま利用できる設計とする）。

## 4. 機能要件

### 4.1 飲食店営業許可 要件判定エンジン

| ID | 内容 | 備考 |
|---|---|---|
| FR-I1.1 | 施設基準（シンクの数、手洗い設備の構造、床・壁・天井の材質、換気設備、照度、給排水設備等）の該当性を判定できること | 令和3年改正で明確化された「洗浄後の手指の再汚染防止構造」（ひねる水栓不可）を必須項目に含める。具体的な数値基準・項目立ては自治体の食品衛生法施行条例により異なりうるため、実装前に一次資料（対象自治体の条例・手引）で確認すること |
| FR-I1.2 | 食品衛生責任者の設置状況（氏名、資格の種別＝調理師・製菓衛生師・栄養士等の資格保有、または講習会受講修了のいずれか）を判定できること。未設置の場合は講習会受講の案内を含めること | 施設ごとに1名以上必須。既存資格による講習免除の要件は、建設業許可の資格者証確認パターン（既存の`ApplicantProfile`のライセンス確認）と同様の構造で入力を受け取る |
| FR-I1.3 | 水質検査（貯水槽水・井戸水等を使用する施設の場合）の要否・実施状況を判定材料として受け取り、該当する場合は水質検査成績書の準備状況を確認できること | 上水道のみを使用する施設では不要。該当性の自己申告を入力とする |
| FR-I1.4 | 上記をまとめて総合判定し、未充足理由の一覧を人間可読なテキストレポートに整形できること | `docs/DESIGN_kobutsu-core.md` 5.1節の`aggregateEligibility`・`formatChecksSection`を再利用する |
| FR-I1.5 | 判定結果のレポートに、「HACCPに沿った衛生管理は許可要件ではなく、許可取得後に必要となる継続義務である」旨の注記を必ず含めること | 1.3節の区別を出力文言レベルで担保する。この注記が無い場合、利用者がHACCP未実施を理由に許可取得を諦める、または逆に許可要件と誤認する事故を防ぐ |

### 4.2 飲食店営業許可 書類生成

| ID | 内容 | 備考 |
|---|---|---|
| FR-I2.1 | 営業許可申請書の記載内容サマリーをdocxで生成できること（申請者・屋号・営業所所在地・営業設備の大要等） | |
| FR-I2.2 | 施設完成後に保健所へ提出する添付書類（営業施設の図面、水質検査成績書〈該当する場合〉、食品衛生責任者資格を証する書類等）のチェックリストを出力できること | 民泊モジュール・技人国ビザモジュールの添付書類チェックリストと同じ考え方を踏襲する |
| FR-I2.3 | 事前相談から許可証交付までの標準的な流れ（①事前相談→②工事着工→③施設完成10〜14日前を目安とした許可申請書提出→④実地検査（営業者立会い必須）→⑤許可証交付）を案内する文書を生成できること | 具体的な提出目安日数・手数料は自治体により異なるため、実装前に対象自治体の一次資料で確認すること |
| FR-I2.4 | 各様式はコアの共通ヘルパーを再利用し、「正式提出様式ではない」旨に加え、「HACCPに沿った衛生管理は別途の継続義務である」旨を明記すること | |

### 4.3 有効期間満了リマインド（コアへの登録）

| ID | 内容 | 備考 |
|---|---|---|
| FR-I3.1 | 許可証交付後、許可証に記載された有効期間年数（自治体・施設により5〜8年の幅がある）を入力として受け取り、許可年月日を起点に満了日を計算できること | 建設業許可・産廃許可の「5年固定」の計算関数はそのまま流用できない。年数を可変で受け取れる新しい計算関数が必要（設計書4.3節で詳細化） |
| FR-I3.2 | 満了日を基準に、余裕を持った更新準備のリマインドタイミング（例: 満了90日前・60日前、満了1か月前の締切）を算出できること | 更新手続きは有効期間満了の概ね1か月前までに行う必要があるとされる（自治体により運用が異なるため一次資料で確認すること）。構造変更が無い限り図面の再提出は不要だが、変更がある場合は再提出が必要となる点を案内文に含める |
| FR-I3.3 | 店舗ごとに異なる自治体・異なる有効期間年数を持つ複数の`LicenseEntry`を1クライアントに登録でき、それぞれ独立してリマインドが算出されること | 複数店舗展開の依頼者を想定（3章） |

### 4.4 インテイク

既存と同様、CLI/スクリプト操作を前提とする。

### 4.5 非機能要件

既存NFR-1〜7・NFR-C1〜C3（`docs/DESIGN_kobutsu-core.md`・
`docs/REQUIREMENTS_sanpai-core.md`等で定義済み）を継承する。加えて:

| ID | 内容 |
|---|---|
| NFR-I1 | 判定結果・生成書類のすべての出力に、「HACCPに沿った衛生管理は許可要件ではなく継続義務である」旨の文言を含めること（FR-I1.5・FR-I2.4） |
| NFR-I2 | 施設基準の具体的な数値基準（シンクの数、照度等）は自治体の食品衛生法施行条例により異なりうるため、コード中に自治体名を直接埋め込まず、入力データとして受け取る設計とすること（既存の`prefectureRules.js`のレジストリパターンを参考にしてよいが、本フェーズでは単一の代表的基準セットの実装に留め、自治体別の条例差分対応は9章の拡張ポイントとする） |

### 4.6 スコープ外（本フェーズで対応しないこと）

- 深夜酒類提供飲食店営業届出（風俗営業等の規制及び業務の適正化等に
  関する法律に基づく、警察署・公安委員会への届出）
- 風俗営業許可（同法に基づく許可。飲食店営業許可とは所管・根拠法が
  異なる）
- 酒類販売業免許（酒税法に基づく、酒類の小売・卸売を行う場合に必要な
  税務署の免許。飲食店内で提供するのみであれば不要だが、酒類の物販を
  行う場合に必要となるため別モジュールの検討対象とする）
- 菓子製造業・惣菜製造業等、飲食店営業以外の食品衛生法上の許可業種
  （令和3年改正後の32業種のうち、飲食店営業以外の31業種）
- HACCPに沿った衛生管理の実施計画書そのものの作成支援（1.3節の通り
  継続義務であり許可要件ではないため、本フェーズの要件判定・書類生成の
  対象に含めない。将来的な別モジュール化は9章で検討する）
- 大規模事業者向けの本格的なHACCP実施（コーデックス委員会の7原則に
  基づく方式）の該当性判定
- 自治体ごとの施設基準条例の差分を網羅的にデータベース化すること
  （NFR-I2参照。本フェーズは代表的基準セットの実装に留める）
- 営業許可取得後の食品表示法・景品表示法等、他法令に基づく届出・表示
  対応

## 5. 受け入れ基準

1. `npm test` が既存分＋新規追加分すべて成功すること
2. 既存モジュールの出力・挙動が変化しないこと（回帰テスト）
3. ダミーデータから施設基準・食品衛生責任者要件の判定、および2種類の
   出力（営業許可申請書サマリー・添付書類チェックリスト）が生成できる
   こと
4. 有効期間年数（5年〜8年の範囲で複数パターン）を変えて満了リマインド
   を計算した際、それぞれ正しい満了日・リマインド日が算出されること
5. 生成される判定レポート・書類のすべてに、HACCPに沿った衛生管理が
   継続義務である旨の注記が含まれること（NFR-I1の確認）

## 6. 前提条件・依存事項

- 施設基準の具体的な数値基準・添付書類の種類は自治体の食品衛生法
  施行条例・保健所の手引により異なるため、対象とする自治体（初期は
  代表的な1〜数自治体を想定）の一次資料を実装前に確認すること
- 食品衛生責任者の資格要件（講習会の実施主体・受講方法を含む）は
  都道府県知事等が定めるため、対象自治体の最新の運用を確認すること
- 有効期間の年数区分（5〜8年のいずれになるか）の具体的な決定基準
  （施設の堅牢性・設備の耐久性の評価方法）は自治体ごとに異なるため、
  本モジュールは年数そのものを判定・予測する機能を持たず、許可証
  交付後の入力値として扱う設計とする（1.3節）
- 対象様式（営業許可申請書）の最新版を対象自治体の公式サイトから
  取得すること（様式は改定される場合があるため、実装直前に再確認
  すること）
