# 0009. 経営事項審査（経審）対応は書類準備支援に限定し、点数計算は対象外とする

Status: Accepted
Date: 2026-09-12

## Context（背景）

競合調査（クリックス社の建設業向け製品が「書類作成・財務諸表・経審分析・
工事経歴書の一括作成」を主要機能としている）を踏まえ、経営事項審査（経審）
対応をM8として検討した。

経審は「経営状況（Y）」「経営規模等（X1・X2）」「技術力（Z）」「社会性等（W）」
を数値化し、総合評定値Ｐ（`P = 0.25X1 + 0.15X2 + 0.2Y + 0.25Z + 0.15W`。
小数点以下四捨五入）として算出する国の制度である
（[CIIC「総合評点Ｐ」](https://www.ciac.jp/keisin/hyotenp)で確認済み）。

調査の結果、以下が判明した。

1. X1（完成工事高評点）・X2（経営規模評点）・Z（技術力評点）は、単純な線形式
   ではなく、国土交通省が業種区分ごとに定める**換算表・係数**（中央建設業
   審査会の答申に基づき定期的に改定される）を用いて算出する。本プロジェクトの
   ような個人開発・低頻度メンテナンス（DEVELOPMENT_GUIDE.md 6章）の体制では、
   これらの表が改定されるたびに追随することが現実的でない。
2. Y（経営状況分析評点）は、**法令上、国土交通大臣の登録を受けた民間の
   経営状況分析機関に申請して算出してもらう**ものであり
   （[国土交通省「経営事項審査及び総合評定値の請求について」](https://www.mlit.go.jp/totikensangyo/const/1_6_bt_000153.html)
   で確認済み）、本ツールが代替・自己計算してよいものではない。
3. 誤った点数を行政書士に提示した場合、入札参加資格に直結する書類の記載
   誤りにつながりうる。判定ロジックに誤りがあっても影響が「気づきの見落とし」
   に留まる要件判定エンジン（§1設計原則）とは異なり、実害の性質が異なる。

一方、**工事経歴書（様式第二号）**は、経審の添付書類であると同時に、
既存の決算変更届（M4のリマインド対象）でも毎事業年度必要になる書類であり、
新規の点数計算ロジックを一切伴わない単純な書類サマリー生成として、
既存の様式生成モジュール（`src/documents/youshiki*.js`）と同じパターンで
実装できる（[工事経歴書の記載例](https://kensetsu-wakaru.com/example-007/)で
書式を確認済み）。

## Decision（決定）

経審対応のM8フェーズ1は、**工事経歴書（様式第二号）のdocxサマリー生成**に
限定する。以下は明示的に対象外とする。

- X1・X2・Y・Z・W各評点、総合評定値Ｐの自動計算
- 経営規模等評価申請書・経営状況分析申請書そのものの生成（点数計算を伴わない
  申請書自体は将来検討の余地があるが、フェーズ1では着手しない）
- 財務諸表（様式第十五号〜十七号）のサマリー生成（工事経歴書よりデータ項目が
  大幅に多く、別途調査・設計が必要なため、着手する場合はM9以降の別フェーズとする）

工事経歴書についても、正式な様式が要求する「元請工事を先に記載し請負代金の額の
大きい順に並べる」という並び順までは自動化するが、**「完工高累計のおおむね7割
に達するまで」「500万円未満（建築1500万円未満）の軽微な工事は10件まで」といった
経審・決算変更届それぞれで異なる選定・抜粋ルールは自動化しない**
（生成物に確認を促す注記を付与し、行政書士本人が最終的な掲載件数を判断する）。
消費税の税込・税抜（経審提出時は税抜が必須）についても、税率を本ツールが
仮定して自動換算することはせず、入力値をそのまま出力し注記で確認を促す。

## Consequences（影響）

- **メリット**: 点数計算という、改定頻度が高く誤りの実害が大きい領域に
  踏み込まずに、既存の決算変更届ワークフローと相乗効果のある書類生成機能を
  安全に追加できる
- **デメリット**: 「経審対応」を謳うにはスコープが限定的（点数シミュレーション
  ができない）。将来的に評点計算を扱う場合は、公式の換算表を都度取得できる
  運用体制（例: 年1回の確認作業をタスク化する等）を別途整備してから着手する
  必要がある
- **見直しのトリガー**: 発注者（行政書士登録後）が実際の経審申請業務で
  点数シミュレーション機能の必要性を強く感じた場合、公式換算表の取得・
  更新手順を含めて再設計する
