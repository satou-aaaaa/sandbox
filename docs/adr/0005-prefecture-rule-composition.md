# 0005. 都道府県固有要件は共通5要件モジュールを改変せず、登録制の追加ルールとして合成する

Status: Accepted
Date: 2026-09（M6着手時点）

## Context（背景）

`docs/PROPOSAL.md` のロードマップではM6を「複数都道府県対応」としている。
建設業許可の法定5要件（経営業務管理体制・専任技術者・財産的基礎・欠格要件・
誠実性）は全国共通の建設業法に基づくが、都道府県によっては独自の運用上の
追加要件・確認事項が存在しうる。

`docs/REQUIREMENTS.md` 8章の前提条件により、**対象都道府県は現時点で
未確定**である。そのため、特定の都道府県の実際の追加要件をハードコードする
ことはできない（内容が分からない、または誤った内容を実装してしまうリスクが
ある）。一方で、対象都道府県が確定した際にスムーズに拡張できるよう、
今のうちに仕組みだけは用意しておく価値がある。

## Decision（決定）

`src/eligibility/rules/*.js`（共通5要件）は直接改変しない。代わりに
`src/eligibility/prefectureRules.js` に、都道府県名をキーとした追加ルールの
登録・取得の仕組み（`registerPrefectureRules` / `getPrefectureRules`）を
用意した。`evaluateEligibility`（`engine.js`）は `profile.prefecture` に
対応するルールが登録されていれば、共通5要件の判定結果にそれを合成する。
未登録の場合（＝現時点のデフォルト）は従来どおり共通5要件のみで判定し、
M1〜M4の既存の挙動には一切影響しない。

対象都道府県が確定し、固有要件の具体的な内容が判明した段階で、
`src/eligibility/prefectures/<都道府県名>.js` のような新規モジュールを追加し、
`registerPrefectureRules("<都道府県名>", checkFn)` を呼び出すだけで
組み込めるようにする。このADR自体、および `src/eligibility/prefectureRules.js`
は実在の都道府県の法的要件を一切含まない（テスト `test/prefectureRules.test.js`
では架空の都道府県名・架空の要件のみを使用している）。

## Consequences（影響）

- **メリット**: 既存の5要件モジュール・テスト・書類生成モジュールへの影響を
  局所化できる。対象都道府県確定後の実装は「新規ルールモジュールを1つ書いて
  登録する」だけで済み、`engine.js` 側の変更は不要
- **デメリット**: 複数の都道府県を同時に扱う運用（例: 複数拠点で別々の
  都道府県の案件を扱う）は現状想定しておらず、`ApplicantProfile.prefecture`
  という単一の文字列キーでの単純なマッチングに留まる。都道府県名の表記揺れ
  （「東京都」と「東京」等）を吸収する仕組みも現状ない
- **見直しのトリガー**: 実際に対象都道府県が確定し追加要件の内容が分かった
  時点で、本ADRの想定どおり拡張できるか実地で検証すること。都道府県名の
  表記揺れが実務上問題になった場合は正規化処理の追加を検討する
