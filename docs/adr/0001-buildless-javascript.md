# 0001. TypeScriptを使わずJSDoc + 素のJavaScriptで実装する

Status: Accepted
Date: 2026-09（M1着手時点、遡って記録）

## Context（背景）

本プロジェクトは行政書士の副業として平日夜間・週末に開発・保守する前提であり、
開発に充てられる時間は限られている。法定要件の判定ロジック（`src/eligibility/`）
のように、型安全性が欲しくなる複雑な条件分岐も含まれる。

## Decision（決定）

TypeScriptのコンパイルステップは導入せず、プレーンJavaScript（ESM,
`"type": "module"`）+ JSDocコメントで型を表現する。VS Code等のエディタでは
JSDocの型注釈だけでも型補完・型チェックがほぼTypeScriptと同等に効く。

型定義は `src/eligibility/types.js` に集約し、すべてのモジュール
（要件判定・書類生成・Webフォーム）がこれを再利用する（唯一の情報源。
ADR-0002も参照）。

## Consequences（影響）

- **メリット**: `node` コマンドで直接実行でき、ビルド・トランスパイル待ち時間が
  発生しない。副業の限られた時間を実装に使える。依存パッケージも
  最小限（本番依存は `docx` のみ）に保てる
- **デメリット**: `tsc` によるコンパイル時型チェックの厳密さはない
  （エディタの型ヒントに依存する）。CIでの型エラー検出は現状できていない
- **見直しのトリガー**: プロジェクトの規模がさらに拡大し（例: M6の複数都道府県
  対応で条件分岐が大幅に増える等）、JSDocの目視確認では型の不整合を
  見逃すリスクが無視できなくなった場合、`tsconfig.json` の `checkJs: true` を
  導入してCIで型チェックのみ行う（コンパイル・ビルドステップは追加しない）
  ことを検討する（`docs/ARCHITECTURE.md` および
  `docs/BEST_PRACTICES_AUDIT.md` にも同様の記載あり）
