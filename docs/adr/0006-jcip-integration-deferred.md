# 0006. JCIP自動連携は本フェーズで実装せず、公開情報の調査結果のみ記録する

Status: Accepted
Date: 2026-09（M6着手時点）

## Context（背景）

`docs/PROPOSAL.md` のロードマップM6には「JCIP連携の検証」が含まれる。
JCIP（建設業許可・経営事項審査電子申請システム）は国土交通省が運営する
電子申請基盤であり、`docs/REQUIREMENTS.md` 1.1節が言及するとおり、
外部インターフェイス仕様が公開されている。

M6の着手にあたり、この公開情報を調査した（2026年9月時点）。

- 国土交通省の公式ページ
  （https://www.mlit.go.jp/tochi_fudousan_kensetsugyo/const/tochi_fudousan_kensetsugyo_const_tk1_000001_00019.html ）
  で「電子申請システム外部インターフェース仕様書」（バージョン1.3。
  2026年7月1日〜適用）と「XML項目定義書・別表」（Excel形式）が公開されている
- データ形式はXML
- 特別な事前申込み手続きの記載は確認できなかった（仕様書自体は
  ページから直接ダウンロード可能）
- 外部インターフェイスに関する問い合わせ先は `ciic.teiantai@ciic.or.jp`
  （件名を「建設業許可等電子申請システム外部インターフェイスに関する照会」
  とすること、との案内あり）

## Decision（決定）

上記の調査結果を記録するに留め、**実際の自動連携コード（XMLの組み立て・
送信処理等）は本フェーズでは実装しない**。理由は以下のとおり。

1. `docs/REQUIREMENTS.md` 1.3節・`docs/DESIGN.md` 1章の設計原則により、
   行政書士登録が完了するまで、報酬を得て官公署に提出する書類の作成・
   提出代理を行うことはできない（2026年法改正で明確化された独占業務）。
   登録前に自動送信の実装を進めることは、この前提と精神的に相容れない
2. 実際のXML項目定義書・別表の内容はまだ本プロジェクトで入手・精査して
   いない（今回はページの存在と概要を確認したのみ）。内容を精査しないまま
   実装すると、誤った形式のデータを組み立てるリスクがある
3. `docs/REQUIREMENTS.md` 8章により対象都道府県も未確定であり、
   JCIPの都道府県別対応状況（対応状況は変化しうるとされている）を
   確認する前提条件も満たされていない

## Consequences（影響）

- **メリット**: 実際には使えない、あるいは誤った実装を作り込むリスクを
  避けられる。将来着手する際の入り口（公式ページのURL・問い合わせ先）を
  記録しておくことで、調査の重複を防げる
- **デメリット**: M6の「JCIP連携」自体は実質的に未着手のままである
- **見直しのトリガー**: 以下がすべて揃った時点で、着手を検討する
  1. 行政書士登録が完了していること（M5の試験運用が実施できる状態）
  2. 対象都道府県が確定していること（`docs/REQUIREMENTS.md` 8章）
  3. 「電子申請システム外部インターフェース仕様書」本文とXML項目定義書を
     実際に入手し、内容を精査していること
  4. 着手の可否・スコープについて発注者（本プロジェクトの場合は開発者自身）
     の判断を得ていること
