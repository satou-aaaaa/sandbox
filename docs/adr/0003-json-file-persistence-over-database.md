# 0003. クライアント情報の永続化にデータベースではなく単一JSONファイルを使う

Status: Accepted
Date: 2026-09（M4）

## Context（背景）

M4のリマインド機能（`reminderDigest.js`）は、複数クライアントの許可情報
（クライアント名・許可年月日・事業年度終了日・連絡先メールアドレス）を
繰り返し参照する必要がある。都度ダミーデータや手打ちの配列を渡す運用では
実案件に使えない。

NFR-2（追加の外部サービス・クラウド環境を必須としない）・NFR-4
（ローカル実行・ローカル保存が前提）という既存の制約があり、個人の副業運用で
管理するクライアント数も現実的には数件〜数十件程度と見込まれる。

## Decision（決定）

SQLite等の組み込みDBやクラウドDBは導入せず、`data/clients.json` という
単一のJSONファイルへ `ClientLicenseRecord[]` をそのまま読み書きする
（`src/reminders/clientStore.js`）。ファイル未存在時は空配列を返し、
初回利用時にエラーにしない。`data/` は `.gitignore` で除外し、
実クライアントデータをリポジトリにコミットしない。

## Consequences（影響）

- **メリット**: 追加の依存パッケージ・実行時プロセス（DBサーバー等）が不要。
  ファイルをテキストエディタで開けば中身を直接確認・修正できる。
  実装・テストが単純（`loadClients`/`saveClients`/`upsertClient`/`removeClient`
  の4関数のみ）
- **デメリット**: 同時書き込みに対する排他制御がない（単一プロセス・
  単一ユーザーでのローカル利用を前提としており、複数プロセスから同時に
  書き込むと後勝ちでデータが失われる可能性がある）。クライアント数が
  数百件を超えるような規模には向かない
- **見直しのトリガー**: 複数拠点・複数端末で同じデータを共有する必要が
  生じた場合、または案件管理の複雑さ（検索・関連データの紐付け等）が
  増した場合は、SQLite（`node:sqlite` 等、追加の外部プロセス不要な組み込みDB）
  への移行を検討する
