# 0021. 正式様式への対応は、まず様式第二号（工事経歴書）をdocxの罫線で再現する（方式B）

Status: Accepted
Date: 2026-10-18

## Context（背景）

様式の出力は内容確認用のサマリー表だけで、提出前に正式様式へ人が転記している（Issue #76）。
「最終レビューと押印だけ」に絞るという目的に対して、この転記が最後に残る手作業になっている。

Issue #76 で比べた方式は次の3つ。

- A. 公式様式（Excel/PDF）のセル・フォーム欄へ値を流し込む
- B. `docx` で正式様式の欄の並びと罫線を再現する
- C. 現状維持＋「どの欄に転記するか」の対応表

発注者（satou さん）の判断（2026-10-18、TODO ボードから「推奨どおりで進める」）により、
Issue の観点（提出頻度・転記の量・レイアウト再現の容易さ・依存を増やさない）で推奨案を選んだ。

確認したこと:

- 様式は建設業法施行規則の別記様式（省令）で定められている。法令は著作権の対象外
  （著作権法第13条第1号）のため、欄の並びを再現して使うことに利用条件上の問題はない。
  一方、都道府県が配布する Excel・PDF ファイルそのものの再配布・改変の可否は様式ごとに
  確かめる必要があり、方式Aではここが残る。
  - 建設業法施行規則 様式第二号: https://laws.e-gov.go.jp/data/MinisterialOrdinance/324M50004000014/621062_1/pict/2FH00000061301.pdf
  - 著作権法第13条: https://laws.e-gov.go.jp/law/345AC0000000048
- 工事経歴書は新規・更新に加えて毎年の決算変更届・経審でも出す。工事1件ごとに8項目以上を
  書き、件数が多く、業種ごとに分けて並べ替えるため、建設業許可の書類の中で転記の量が最も多い。

## Decision（決定）

- 対象: 様式第二号（工事経歴書）から始める（`src/documents/youshiki2-form.js`）。
- 方式: B。`docx` だけで正式様式の欄の並び（注文者・元請又は下請の別・JVの別・工事名・
  工事現場・配置技術者・請負代金の額と内訳・工期）と罫線を再現し、A4横・業種ごとに1枚で出す。
  本番依存は `docx` のまま増やさない（ADR-0001・NFR の方針どおり）。
- 入力項目が無い欄（JV・工事現場・PC等の内訳）は空欄で出し、手書きで補う。足りない欄は
  確認事項として文書の最後に列挙する（方式Cの要素を取り込む）。
- 注記: 罫線版でも「人が確認する」旨の赤字注記は残す（`buildFormLayoutDisclaimerParagraph`）。
  自動押印・自動提出はしない。
- 既存のサマリー版（`youshiki2.js`）は残し、Web画面では両方を出す。並び順は共通の
  `compareWorkRecords` を使い、2つの出力の順序がずれないようにする。

方式Aを選ばなかった理由: PDF/Excel を扱う依存の追加が必要で、様式ファイルの利用条件・
配布形式が都道府県ごとに異なり、対象都道府県（#81）の様式の確認待ちが残るため。

## Consequences（影響）

- 転記の大半（工事の行・並び順・千円単位への換算・合計）が不要になり、空欄の補記と確認だけになる。
- 正式様式との差（ページごとの小計欄が無い、字詰め・行の高さの違い）は残る。
  許可行政庁が様式の厳密な一致を求める場合は、そのまま提出できない。
- 見直しのきっかけ: 対象都道府県（#81）の様式が電子ファイルで手に入り再配布・改変の条件が
  はっきりしたとき、または罫線版で窓口から差し戻しがあったときは方式Aを再検討する。
  効果があれば、様式第一号・第六号・第七号・第八号・第二十号の二へ同じ方式で広げる。
