# 建設業許可 自動化プロダクト — ソフトウェア開発提案書

2026年9月時点。詳細な体裁付き版は別途docxで作成済み（会話履歴を参照）。
このファイルは開発の進捗に合わせて随時更新する「生きた」提案書として管理する。

## 1. 目的・背景

行政書士を副業として展開するにあたり、限られた時間（平日夜間・週末中心）で継続的に
サービス提供できる体制を作るため、「システムによる自動化を最優先とする」方針を採用した。
建設業許可（国交省がJCIPの外部インターフェイス仕様書を公開しており、5年更新・毎年の
決算変更届という反復業務を持つ）を自動化プロダクトの旗艦分野として選定している。

## 2. 開発の基本方針

- **ビルドレス構成**: TypeScriptのコンパイルステップを挟まず、JSDoc + 素のJavaScriptで実装
- **テストファースト**: 法定要件のロジックは必ず `node --test` のユニットテストを伴わせる
- **人手レビューを唯一のボトルネックとして設計に明示**: 行政書士本人のレビュー・職印は省略できない
- **小さく作って検証し、段階的に拡張する**

## 4. スコープ定義（フェーズ1: MVP）

**対象とすること**
- 実際に活動予定の1都道府県に絞る
- 優先様式（第一号・第六号・第七号・第八号・第二十号の二）から対応
- インテイクはまずJSON/CLIベース

**対象外（フェーズ1では扱わない）**
- JCIPとの自動連携
- 複数都道府県対応
- 顧客向け入力フォーム・ポータル
- メール等の自動通知連携

## 6. リスクと法的制約

- 行政書士登録が完了するまで、本ツールを使って有償で書類作成・提出代理を行うことはできない
- 要件判定エンジンの結果は一次スクリーニングに過ぎず、最終責任は常に本人が負う
- 都道府県ごとに様式・運用が異なる
- JCIPの都道府県別対応状況は今後も変化しうる
