# 要件定義書 — 産業廃棄物収集運搬業許可モジュール

version: 0.1 / 2026-09 作成
対象: kensetsu-kyoka-toolkit の拡張（`docs/DESIGN_kobutsu-core.md` で設計したコア基盤の3例目としての実装）

## 0. 本書の位置づけ

本書は、許認可自動化コア（`src/core/`。`docs/DESIGN_kobutsu-core.md` で設計）の
上に「産業廃棄物収集運搬業許可」アドオンを追加する開発の要件定義書。
コア自体の設計・古物商許可モジュールの詳細は `docs/DESIGN_kobutsu-core.md`・
`docs/REQUIREMENTS_kobutsu-core.md` を参照し、本書では繰り返さない。
開発環境構築・コーディング規約・Git運用は既存の `docs/DEVELOPMENT_GUIDE.md`
をそのまま適用する。

**前提**: 本書は古物商許可モジュールの開発（コア抽出を含む）が完了している
ことを前提とする。コア抽出が未実施の場合は、先に
`docs/REQUIREMENTS_kobutsu-core.md`・`docs/DESIGN_kobutsu-core.md` に基づく
開発を完了させること。

## 1. プロジェクト概要

### 1.1 背景

産業廃棄物収集運搬業許可は、建設業許可のクライアント層と重なりが大きい
（建設業者が自社以外の産業廃棄物を運搬する場合に必要となるため）分野で
あり、既存の建設業許可クライアントへのクロスセルが見込める。また、
許可の有効期間が5年で更新制という点が建設業許可と構造的に同じであり、
コアのリマインドエンジン（`src/core/reminders/`）・
`src/licenses/construction/reminders/renewalSchedule.js` の計算ロジックを
そのまま流用できる可能性が高い。

一方で、①複数都道府県にまたがる申請が実務上前提になりやすい点
（積込み地・荷下ろし地それぞれの都道府県で許可が必要）、②JWセンター
（日本産業廃棄物処理振興センター）講習の修了証に5年という別の有効期限が
あり、許可の更新とは別に管理が必要な点、の2点が建設業許可・古物商許可
にはなかった新しい複雑性として存在する。

### 1.2 目的

1. 産業廃棄物収集運搬業許可（一般。特別管理産業廃棄物は対象外）の
   要件判定（欠格事由・経理的基礎・講習修了）を実装する
2. 許可申請書・事業計画書のサマリーをdocxで生成する
3. 許可の更新（5年）・講習修了証の有効期限、2種類のリマインドを
   コアのリマインドエンジンに登録する

### 1.3 重要な制約（法的前提）

- 廃棄物の処理及び清掃に関する法律（廃棄物処理法）上、報酬を得て
  官公署に提出する許可申請書類を作成する行為は行政書士の独占業務に
  含まれる。行政書士登録が完了するまで、本ツールを使って有償で書類
  作成・提出代理を行うことはできない（既存原則を継承）
- 本システムの判定結果は一次スクリーニングであり、許可を保証しない
  （既存原則を継承）
- 「経理的基礎」（4.2節）の判定は、決算書の解釈という会計的な専門性を
  伴う。本ツールは形式的な数値チェック（債務超過の有無等）に留め、
  実質的な財務判断は行政書士本人（必要に応じて税理士等の専門家と連携）
  が行うことを前提とする

## 2. 用語集

| 用語 | 説明 |
|---|---|
| 産業廃棄物収集運搬業 | 廃棄物処理法に基づき、産業廃棄物の収集・運搬を業として行うために都道府県知事等の許可を受けた事業 |
| 特別管理産業廃棄物 | 産業廃棄物のうち爆発性・毒性・感染性等を有するもの。本開発では対象外（4.6節） |
| JWセンター | 日本産業廃棄物処理振興センター。収集運搬業の許可要件となる講習を実施する機関 |
| 経理的基礎 | 事業を的確・継続的に行うに足りる経理的な基盤があること（許可要件の一つ） |
| 積替え保管 | 収集した廃棄物を一時的に保管する行為を伴う運搬。本開発では対象外（4.6節） |

## 3. 想定利用者・利用シーン

既存の建設業許可・古物商許可と同じ（発注者本人が行政書士登録後、
自身の業務で使用する。CLI/スクリプト操作が前提）。想定シーンとして、
建設業許可の既存クライアントから「産廃収集運搬の許可も取りたい」と
相談された際に、同じクライアントレコード（`ClientRecord`）に許可を
追加する形での利用を想定する（`licenseCategory: "sanpai"` の
`LicenseEntry` を既存クライアントへ追加できることが重要。FR-S3.1参照）。

## 4. 機能要件

### 4.1 産廃 要件判定エンジン

| ID | 内容 | 備考 |
|---|---|---|
| FR-S1.1 | 欠格事由（廃棄物処理法第14条第5項第2号。同号は第7条第5項第4号イ〜チを包含する形で規定）を判定できること | 号立てはe-Gov法令検索で原文確認済み（2026年9月）。想定より項目数が多く、「拘禁刑以上の刑から5年未満」「この法律・浄化槽法違反または特定の暴力犯罪による罰金刑から5年未満」「許可取消しから5年未満（役員の60日遡及を含む）」に加え、案文時点で漏れていた「心身の故障により業務を適切に行うことができない者」「破産手続開始の決定を受けて復権を得ない者」「事業廃止届出（取消し逃れ）から5年未満」「不正・不誠実行為のおそれ」も含む8区分。詳細はDESIGN_sanpai-core.md 3章のSanpaiKekkakuInput参照 |
| FR-S1.2 | 申請者（法人の場合は役員を含む）がJWセンター講習を修了しており、修了証の発行日から申請時点で5年以内であることを判定できること | 講習修了証の発行日を入力とし、申請予定日との差分を計算する。単純な合否だけでなく「あと何年何ヶ月で講習の再受講が必要か」を出力できることが望ましい（FR-S4.2のリマインドと連動） |
| FR-S1.3 | 経理的基礎について、直近3期の決算情報（自己資本額・当期損益等）を入力として受け取り、債務超過に該当しないかを形式的にチェックできること。該当する場合は「直ちに不合格」とはせず、改善計画等による説明の余地がある旨の注記付き警告とすること | 建設業許可の`zaisanKiso.js`と類似のパターンだが、産廃の経理的基礎は環境省通知に基づく複数の算定パターン（直近1期の基準を満たさなくても過去3〜5期の平均等で救済される場合がある）があるため、本フェーズでは「直近期が債務超過かどうか」の単純な形式チェックに留め、複雑な救済パターンの判定は対象外とする（4.6節） |
| FR-S1.4 | 運搬施設（車両・容器等）について、飛散・流出・悪臭防止の措置が取られているかの自己申告を受け取り、必ず人手確認を促す警告を出せること | 建設業許可の`seijitsusei.js`と同様、現地確認が必要な項目は自己申告＋警告に留める |
| FR-S1.5 | 上記をまとめて総合判定し、未充足理由の一覧を人間可読なテキストレポートに整形できること | コアの`formatChecksSection`を再利用 |

### 4.2 産廃 書類生成

| ID | 内容 | 備考 |
|---|---|---|
| FR-S2.1 | 産業廃棄物収集運搬業許可申請書の記載内容サマリーをdocxで生成できること | |
| FR-S2.2 | 事業の実施の方法（事業計画書）の記載内容サマリーをdocxで生成できること。運搬車両・運搬容器の一覧を表形式で出力できること | コアの`buildHeaderedTable`（工事経歴書で使用したものと同じヘルパー）を再利用する |
| FR-S2.3 | 各様式はコアの`buildDisclaimerParagraph`等を再利用し、「正式提出様式ではない」旨を明記すること | |
| FR-S2.4 | 対象都道府県の様式レイアウト・記載要領は発注者から共有を受けた上で確定すること | 産廃は都道府県ごとの様式差異に加え、政令市（別途申請窓口になる場合がある）の存在も確認すること |

### 4.3 産廃 リマインド（コアへの登録）

| ID | 内容 | 備考 |
|---|---|---|
| FR-S3.1 | 許可の更新期限を、既存の建設業許可と同じ月単位丸め計算ロジック（`calcRenewalSchedule`相当）で算出し、コアのスケジュール・レジストリ（`registerScheduleFn("sanpai", ...)`）に登録できること。ただし有効期間は建設業許可と異なり一律5年ではない（下記備考） | 廃棄物処理法施行令第6条の9により、有効期間は「新規許可: 5年」「更新時、優良認定基準（環境省令）に適合: 7年」「更新時、優良認定基準に適合しない: 5年」の3区分（e-Gov法令検索で原文確認済み・2026年9月）。建設業許可の`calcRenewalSchedule`は期間を固定5年でハードコードしているため、そのまま呼び出すのではなく有効期間（5または7）を引数化した計算に対応させる必要がある。優良認定の判定自体（環境省令の基準適合確認）は本フェーズの対象外とし、有効期間年数は利用者が別途確認して入力する前提とする |
| FR-S3.2 | 講習修了証の有効期限（発行日から5年）についても、許可更新とは別のリマインド項目として算出できること。次回更新に間に合うよう、許可満了日より前に講習修了証が切れる場合は、より早いタイミングで警告が出ること | 許可満了日と講習修了証の期限、2つの日付のうち早い方を基準にリマインドの優先度を上げる、というロジックが必要（設計書で詳細化） |
| FR-S3.3 | 産廃許可を追加する際、既存の建設業許可を持つクライアントレコードに対して`licenseCategory: "sanpai"`の`LicenseEntry`を追加できること（クライアント自体は新規作成しない） | 既存の`upsertClientLicense`（コア）がそのまま使えることの確認 |

### 4.4 インテイク

既存と同様、CLI/スクリプト操作を前提とする（Webフォーム対応は対象外）。

### 4.5 非機能要件

既存NFR-1〜7・NFR-C1〜C3（`docs/DESIGN_kobutsu-core.md`）を継承する。

### 4.6 スコープ外（本フェーズで対応しないこと）

- 特別管理産業廃棄物の収集運搬業許可
- 積替え保管を伴う許可
- 複数都道府県・政令市にまたがる同時申請への対応（本フェーズはまず
  自都道府県分から着手する。建設業許可のM6と同じ位置づけの将来課題）
- 経理的基礎の複雑な救済パターン（過去複数期平均等）の自動判定
- 産業廃棄物処分業許可（収集運搬業とは別の許可。将来の拡張候補）

## 5. 受け入れ基準

1. `npm test` が既存分＋新規追加分すべて成功すること
2. 既存の建設業許可・古物商許可機能の出力・挙動が変化しないこと（回帰テスト）
3. 産廃について、ダミーデータから欠格事由・講習修了・経理的基礎の判定、
   および2様式（許可申請書・事業計画書）のdocxサマリー生成ができること
4. 建設業許可の既存クライアントに産廃許可を追加した際、決算日等の
   会社単位の情報が重複入力されず、リマインド一覧に両方の許可が
   区別して表示されること（ADR-0008の複数許可対応が、許可種別を
   またいでも機能することの確認）
5. 講習修了証の期限が許可満了日より早く到来する場合に、それを検知した
   リマインドが生成されること

## 6. 前提条件・依存事項

- 実際に活動予定の都道府県が確定していること
- 廃棄物処理法第14条の欠格事由・経理的基礎の判定基準について、
  e-Gov法令検索および環境省の関連通知を一次資料として確認すること
  → **2026年9月に確認済み**。欠格事由は第14条第5項第2号（第7条第5項
  第4号イ〜チを包含）、有効期間は施行令第6条の9（新規5年／更新時は
  優良認定の有無により7年または5年）。上記FR-S1.1・FR-S3.1に反映済み
- 対象様式（許可申請書・事業計画書）の正式レイアウトを発注者から
  共有を受けること
