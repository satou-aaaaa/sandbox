## 1. プロジェクト概要

### 1.1 背景

農地転用許可（農地法第4条・第5条）は、建設業許可・産業廃棄物収集運搬業許可の
クライアント層と重なりが大きい分野である。建設業者が資材置場・駐車場・
太陽光発電設備用地等を確保する際に自己所有農地を転用する（4条）、あるいは
農地を取得・賃借して同様の用途に転用する（5条）ケースは実務上頻繁に発生し、
既存クライアントへのクロスセルが見込める。産業廃棄物収集運搬業許可の
クライアントが中間処理施設用地を農地に求めるケースも同様である。

一方で、農地転用許可には既存3モジュール（建設業許可・古物商許可・産業廃棄物
収集運搬業許可）のいずれとも異なる、新しいリマインドの構造上の特徴がある。

- 建設業許可・産業廃棄物収集運搬業許可のような「更新（有効期限）」の概念が
  存在しない。許可は一回限りであり、許可を受けた後に再度手続きが必要になる
  ことは原則ない
- その代わり、許可には「許可条件」が付されることが多く、条件の内容として
  「工事着手期限（許可後おおむね1年以内に転用に供する見込みがあることが
  審査時点で求められ、これが許可条件として明記される運用が一般的）」
  「転用の完了・完了報告の期限（工事完了後、遅滞なく完了報告書を提出する
  義務）」等、履行しなければ許可の取消し（農地法第51条）につながり得る
  期限が個別に設定される
- 古物商許可の「変更トリガー型」（変更という出来事が起きた場合のみ発生する
  リマインド）に近い構造だが、古物商許可が追跡するのは「許可の有効性を保つ
  ための届出義務」であるのに対し、農地転用許可が追跡するのは「個々の許可に
  個別に付された条件の履行状況」である点が異なる。本開発では、これを
  「条件履行期限型」という新しいリマインドパターンとして設計・実装する
  （`docs/DESIGN_nouchi-tenyo-core.md` 4章）

### 1.2 目的

1. 農地転用許可（農地法第4条：自己転用、第5条：権利移動を伴う転用）の
   要件判定（立地基準：農地区分ごとの許可可否、一般基準：転用の確実性・
   周辺農地への被害防除措置等）を実装する
2. 許可申請書・事業計画書のサマリーをdocxで生成する
3. 許可条件として付された「工事着手期限」「転用の完了・完了報告期限」を
   コアのリマインドエンジンに「条件履行期限型」として登録する。履行済み
   フラグが立った項目はリマインドを止め、コアのリマインド・レジストリ
   （`registerScheduleFn`）契約を変更せずに実現できるかを検証する

### 1.3 重要な制約（法的前提）

- 農地法上、報酬を得て官公署（農業委員会・都道府県）に提出する農地転用
  許可申請書類を作成する行為は、行政書士法における行政書士の独占業務に
  含まれる。行政書士登録が完了するまで、本ツールを使って有償で書類作成・
  提出代理を行うことはできない（既存の`docs/REQUIREMENTS_kobutsu-core.md`
  1.3節と同じ制約。許可種別が変わってもこの制約自体は変わらない）
- 本システムの判定結果は「申請前の一次スクリーニング」であり、
  「許可が下りることを保証するもの」ではない。UIやドキュメント上の文言でも
  この前提を誤解させる表現をしないこと（既存原則を継承）
- **立地基準（農地区分の認定）は、本ツールが自動で確定できるものではない。**
  農地が「農用地区域内農地（青地）」「甲種農地」「第1種農地」「第2種農地」
  「第3種農地」のいずれに該当するかの最終的な認定は農業委員会・都道府県が
  行うものであり、本ツールは申請者の自己申告（または行政書士が農業委員会
  への事前相談で確認した内容）を入力として形式的な一次判定を行うに
  留まる。出力物には必ずその旨を明記すること
- **市街化区域内の農地転用は対象外とする。** 市街化区域内では農地法第4条・
  第5条の「許可」ではなく農業委員会への「届出」で足りる（許可制度の対象外）
  ため、本モジュールは市街化調整区域・非線引区域における「許可」案件の
  みを対象とし、届出案件（届出書生成・届出手続の判定）は本フェーズの
  対象外とする（4.6節）
- 農地法第4条・第5条の許可基準（立地基準・一般基準）・欠格事由相当の
  不許可事由を実装する際は、
  [e-Gov法令検索の農地法本文](https://laws.e-gov.go.jp/law/327AC0000000229)、
  および農林水産省「農地法の運用について」「農地法関係事務処理要領」等の
  通知を一次資料として確認すること。本書8章に相当する参考整理は設けず、
  本書1.1節・4章の記載自体が「実装着手前に一次資料で確定させるための
  出発点」であり、本書の記載のみで実装を進めないこと（既存プロジェクトが
  古物商許可・産廃許可で採用してきたのと同じ慎重な方針を踏襲する）

## 2. 用語集

| 用語 | 説明 |
|---|---|
| 農地転用 | 農地を農地以外の用途に転用すること |
| 農地法第4条許可 | 自己所有の農地を自ら転用する場合に必要な許可（自己転用） |
| 農地法第5条許可 | 農地を転用目的で取得・賃借する等、権利移動を伴う転用の場合に必要な許可 |
| 許可権者 | 市街化区域外の農地転用許可を行う者。都道府県知事、または農林水産大臣の指定を受けた指定市町村の長。4haを超える転用は農林水産大臣への協議が必要 |
| 農業委員会 | 市町村に置かれる行政委員会。農地転用許可申請の受付・意見具申（知事許可の場合）、市街化区域内の届出受理を行う |
| 立地基準 | 転用しようとする農地の区分（農用地区域内農地・甲種農地・第1種農地・第2種農地・第3種農地）に応じて許可の可否を判断する基準 |
| 一般基準 | 転用の確実性（資力・信用、工事計画等）・周辺農地への被害防除措置等、案件の内容に着目して許可の可否を判断する基準 |
| 農用地区域内農地（青地） | 市町村の農業振興地域整備計画で農用地区域に指定された農地。原則不許可で、転用には先に農振除外の手続が必要 |
| 甲種農地・第1種農地 | 良好な営農条件を備えた農地。原則不許可（例外は限定的） |
| 第2種農地・第3種農地 | 市街地化の進行度合いが高い等、周辺の他の土地で代替が困難な場合や、原則許可となる農地区分 |
| 許可条件 | 許可証に付される、転用の実施にあたって遵守すべき条件（工事着手期限・完了報告義務等） |
| 工事着手期限 | 許可条件として付されることが多い、転用工事に着手すべき期限 |
| 完了報告 | 転用工事が完了した際に、遅滞なく農業委員会へ提出することが求められる報告 |
| 条件履行期限型 | 本開発で新設するリマインドパターン。許可そのものの有効期限ではなく、個々の許可に付された条件（工事着手・完了報告等）の履行期限を追跡する方式 |

## 3. 想定利用者・利用シーン

既存の建設業許可・古物商許可・産業廃棄物収集運搬業許可と同じ（発注者本人が
行政書士登録後、自身の業務で使用する。CLI/スクリプト操作が前提）。想定
シーンとして、建設業許可や産業廃棄物収集運搬業許可の既存クライアントから
「資材置場・駐車場・処理施設用地として農地を転用したい」と相談された際に、
同じクライアントレコード（`ClientRecord`）に農地転用許可を追加する形での
利用を想定する（`licenseCategory: "nouchi-tenyo"` の `LicenseEntry` を
既存クライアントへ追加できることが重要。FR-N3.5参照）。

## 4. 機能要件

### 4.1 農地転用許可 要件判定エンジン

| ID | 内容 | 備考 |
|---|---|---|
| FR-N1.1 | 適用条文（4条：自己転用／5条：権利移動を伴う転用）を入力として受け取り、判定結果・書類サマリーの見出しに反映できること | 5条の場合は譲受人・借主等の権利取得者情報も入力できること |
| FR-N1.2 | 立地基準として、転用対象農地の区分（農用地区域内農地・甲種農地・第1種農地・第2種農地・第3種農地）の自己申告を受け取り、区分ごとの原則的な許可可否を判定できること。農用地区域内農地・甲種農地・第1種農地は原則不許可とし、例外事由に該当する場合はその旨の入力を受け付け「例外に該当する可能性がある」という注記付きの結果とすること。第2種農地は周辺に代替可能な土地がない場合のみ許可対象、第3種農地は原則許可とすること | **農地区分の最終認定は農業委員会が行うものであり、本判定はあくまで自己申告に基づく形式的な一次判定である旨を必ず結果に含めること**（1.3節）。正確な区分の定義・例外規定の要件は農地法施行令・施行規則を一次資料で確認すること |
| FR-N1.3 | 一般基準として、転用の確実性（資力・信用。融資内諾書・自己資金証明等の有無）、工事計画・工程表の有無、周辺農地への被害防除措置（排水計画等）の有無を判定できること。いずれか未充足の場合は不合格とすること | 建設業許可の`zaisanKiso.js`・産廃許可の`keiriKiso.js`と同様、財務・計画面の確認は形式的なチェックに留める |
| FR-N1.4 | 隣接農地所有者等の同意の有無を任意入力として受け取り、未取得の場合は「都道府県・農業委員会の運用によって要否が異なるため、必ず事前相談で確認すること」という警告（合否には影響しない）を出せること | 建設業許可の`seijitsusei.js`・産廃許可の運搬施設要件と同様、機械的に判定しきれない項目は自己申告＋警告に留める |
| FR-N1.5 | 上記をまとめて総合判定し、未充足理由の一覧を人間可読なテキストレポートに整形できること | コアの`formatChecksSection`を再利用 |
| FR-N1.6 | 転用対象農地の面積が4ヘクタールを超える場合、都道府県知事等が許可をする前にあらかじめ農林水産大臣への協議が必要となる旨を警告できること（合否には影響しない） | **2026年9月実装済み**（`eligibility/daijinKyogi.js`。農地法附則2項1号・3号。e-Gov法令検索で確認済み）。協議の結果（許可が下りるかどうか）自体は本ツールの対象外であり、審査の長期化を見込むべき旨の案内に留める |

### 4.3 農地転用許可 条件履行期限型リマインド（コアへの登録・新パターン）

農地転用許可には建設業許可・産業廃棄物収集運搬業許可のような更新制度
（有効期限）が無い。その代わり、許可条件として付された「工事着手期限」
「転用の完了・完了報告期限」という、履行しなければ許可取消しにつながり
得る期限を、履行済みになるまで追跡する必要がある。

| ID | 内容 | 備考 |
|---|---|---|
| FR-N3.1 | 農地転用許可のクライアントについては、満了日ベースの更新リマインド（建設業許可の`renewal-early-notice`等）を一切生成しないこと | 農地転用許可には更新の概念が無いため。コアのプラグイン方式（`registerScheduleFn`）が「対象許可種別ごとに全く異なるリマインド方式を持てる」ことの4例目の確認を兼ねる |
| FR-N3.2 | 許可条件として工事着手期限が付されている場合、その期限日を入力するとリマインドが生成できること。着手済み（履行済み）であることを記録すると、以後そのリマインドが生成されなくなること | 期限が付されていない許可（着手期限の条件が無い案件）の場合はリマインドを生成しないこと |
| FR-N3.3 | 許可条件として転用の完了・完了報告の期限が付されている場合、同様にリマインドが生成でき、報告済みを記録すると以後生成されなくなること | 同上 |
| FR-N3.4 | 工事着手期限・完了報告期限のリマインドには、期限を超過した場合に許可取消し（農地法第51条）等のリスクがある旨の注記を含めること | コアの`ScheduleFn`契約（`(license) => ScheduleItem[]`）を変更せずに実現すること。基準日（本日日付）をスケジュール計算関数に渡さなくても実現できる設計とすること（設計判断は`docs/DESIGN_nouchi-tenyo-core.md`4章に記載する） |
| FR-N3.5 | 農地転用許可を追加する際、既存の建設業許可・産業廃棄物収集運搬業許可等を持つクライアントレコードに対して`licenseCategory: "nouchi-tenyo"`の`LicenseEntry`を追加できること（クライアント自体は新規作成しない） | 既存の`upsertClientLicense`（コア）がそのまま使えることの確認 |

### 4.6 スコープ外（本フェーズで対応しないこと）

- 市街化区域内の農地転用（農業委員会への「届出」で足りる案件。1.3節参照）
- 農地法第3条許可（転用を伴わない、農地のまま行う権利移動）
- 4haを超える転用で農林水産大臣への協議が必要となる案件の特別フロー:
  **2026年9月・協議の要否の警告表示のみ実装済み**（`eligibility/daijinKyogi.js`。
  農地法附則2項1号・3号）。合否には影響させず、審査が長期化する見込みで
  ある旨の警告に留める。協議そのものの手続支援（大臣協議資料の作成等）は
  引き続き対象外
- 農用地区域からの除外手続（農振除外。転用許可の前提となる別手続であり、
  本開発では「農用地区域内農地は原則不許可」という判定結果を返すに留める）
- 一時転用（工事期間中の仮設道路等）における農地復元期限の管理:
  ✅ 2026年9月実装済み（`NouchiTenyoLicenseDetail.restorationDeadlineIso`・
  `restored`。9章参照）
- 転用完了後の定期的な実施状況報告（露天資材置場等における完了後複数年に
  わたる定期報告義務）の自動リマインド化。本フェーズは「工事着手期限」
  「完了報告期限」の2種類のみを対象とし、それ以降の継続的な報告義務管理は
  将来の拡張候補とする（9章）
- 複数都道府県・複数農業委員会にまたがる同時申請への対応
- 地目変更登記（転用完了後に法務局で行う別手続）のリマインド化

## 5. 受け入れ基準

1. `npm test` が既存分＋新規追加分すべて成功すること
2. 既存の建設業許可・古物商許可・産業廃棄物収集運搬業許可・住宅宿泊事業
   届出機能の出力・挙動が変化しないこと（回帰テスト）
3. 農地転用許可について、ダミーデータから立地基準・一般基準の判定、および
   2様式（許可申請書・事業計画書）のdocxサマリー生成ができること
4. 建設業許可・産業廃棄物収集運搬業許可の既存クライアントに農地転用許可を
   追加した際、リマインド一覧に両方（または複数）の許可が区別して表示
   されること（ADR-0008の複数許可対応が、許可種別をまたいでも機能する
   ことの確認）
5. 工事着手期限・完了報告期限をそれぞれ設定した場合に、期限に応じた
   リマインドが正しく生成されること。履行済みフラグ（着手報告済み／
   完了報告済み）を立てると、該当するリマインドが生成されなくなること
6. 工事着手期限・完了報告期限のいずれかを過ぎている場合、通常のリマインド
   文言に加えて許可取消し等のリスクに関する注記が含まれること
7. コアのリマインド・レジストリ契約（`registerScheduleFn`・`ScheduleFn`の
   シグネチャ）を変更せずに、本モジュールの「条件履行期限型」を実装
   できていること（NFR-N3・FR-N3.4の確認を兼ねる）

## 6. 前提条件・依存事項

- 実際に活動予定の都道府県・農業委員会（指定市町村を含む）が確定していること
- 農地法第4条・第5条の立地基準・一般基準、および許可条件（工事着手期限・
  完了報告義務等）の標準的な内容について、e-Gov法令検索・農林水産省の
  関連通知（「農地法の運用について」「農地法関係事務処理要領」等）・
  対象都道府県が公開する審査基準を一次資料として確認すること
- 対象様式（許可申請書・事業計画書）の正式レイアウトを発注者から共有を
  受けること
- 市街化区域内かどうか（届出対象かどうか）の切り分けを、案件ごとに
  事前相談の段階で確認する運用を発注者側で担保すること（本ツールは
  切り分け自体を自動判定しない。4.6節）
