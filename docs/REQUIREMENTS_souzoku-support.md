# 要件定義書 — 相続関連（遺言書・遺産分割協議書）支援モジュール

version: 0.1 / 2026-09 作成
対象: kensetsu-kyoka-toolkit の拡張（許認可自動化コアの周辺ツールとしての新規実装）

## 0. 本書の位置づけ

本書は、これまでの許認可アドオン群（建設業許可・古物商許可・産業廃棄物
収集運搬業許可・住宅宿泊事業届出・在留資格「技術・人文知識・国際業務」）
とも、`docs/REQUIREMENTS_uketsuke-portal.md`（BtoB下請けケース管理
ポータル）とも異なる、**質的に新しい応用**を対象とする。

これまでの許認可アドオンは、要件判定エンジン（`RequirementCheckResult`
の積み上げ）を使って「欠格事由に該当するか」「許可要件を満たすか」という
**合否（pass/fail）判定**を行うものだった。本モジュールが転用するのは、
要件判定エンジンではなく、その根底にある「入力から機械的なルールに
基づき、理由付きの結果を返す」という設計の考え方そのものであり、
実際に計算する内容は合否ではなく**法定相続人・法定相続分という「分配」**
である。この違いから、本モジュールはコアの `RequirementCheckResult` /
`EligibilityResult` 型・`aggregateEligibility`（集約ロジック）を
そのまま使わず、独自の結果型を新設する（設計書2章・3章で詳細化）。

また、`uketsuke-portal` と同じく、コアの許可レジストリ
（`registerScheduleFn`・`LicenseEntry`）は使わない**独立した業務ドメイン**
として実装する。コアが提供する再利用対象は「docx共通ヘルパー」
（`src/core/documents/common.js`）と「リマインド一覧の表示ロジック」
（`bucketizeAlerts`・`formatReminderDigest`）のみである。

開発環境構築・コーディング規約・Git運用は既存の
`docs/DEVELOPMENT_GUIDE.md` を適用する。

**本モジュールは、これまでのどのモジューよりも「職域の境界線」が
厳格である。1.3節・4.6節・6章を特に注意して読むこと。**

## 1. プロジェクト概要

### 1.1 背景

行政書士の業務範囲の中でも、相続関連（遺言書作成支援・遺産分割協議書
作成）は需要が大きい分野である一方、隣接する司法書士・税理士・弁護士の
独占業務との境界が細かく入り組んでおり、誤って職域を越えた業務を
行ってしまうリスクが他分野よりも高い。特に「相続人間に争いがあるか
どうか」という、法律的には非常に重要でありながら定型的な入力からは
機械的に判定できない分岐点が、業務範囲の可否そのものを左右する
（弁護士法第72条: 争いがある場合の代理交渉は弁護士の独占業務）。

一方で、法定相続人・法定相続分の算出そのものは、民法900条・901条
（代襲相続を含む）という明文化された機械的なルールに基づく計算であり、
これまでコアで培ってきた「入力から、理由（根拠条文）付きの結果を返す」
という設計の考え方が、合否判定以外の場面でも転用できることを示す
良い題材である。この点で、本モジュールは技術的には
「要件判定エンジンの第2の使い道（判定ではなく計算）の実証」、
事業的には「行政書士が単独で完結できる相続業務（争いのないケース）に
特化した支援ツール」という2つの意味を持つ。

### 1.2 目的

1. 家族構成の入力から、法定相続人と法定相続分を民法900条・901条の
   規定に基づき自動計算する
2. 財産目録・遺産分割協議書のサマリーをdocxで生成する
3. 自筆証書遺言の文案作成を支援する（民法968条の方式要件を踏まえる）
4. 相続手続きに関連する主要な期限（相続放棄・相続税申告・遺留分侵害額
   請求）を、既存のリマインド表示ロジックと同じ考え方で管理する

### 1.3 重要な制約（職域の境界線。最重要）

- **行政書士が対応できる範囲は「当事者間に争いがない場合」に限られる**。
  遺産分割協議書の作成は、相続人全員の合意が既に形成されていることを
  前提とした「合意内容の書面化」であり、合意形成そのものの仲介・
  代理交渉・説得は行政書士の業務範囲外である（弁護士法72条）。本モジュール
  は「争いの有無」を自動判定しない。争いの兆候があるかどうかは必ず
  発注者（行政書士）が人手で確認し、案件レコードにフラグとして記録する
  設計とする（`SuccessionCaseRecord.hasDisputeAmongHeirs`。設計書3章）
- **家庭裁判所に提出する書類の作成は行政書士の業務範囲外**である
  （弁護士・司法書士の職域）。相続放棄申述書・遺産分割調停申立書等は
  本モジュールの対象外とする（4.6節）。本モジュールが相続放棄の「期限」
  を計算・リマインドすることと、相続放棄「申述書の作成」自体は別物で
  あり、両者を混同しないこと
- **不動産の相続登記は司法書士の業務範囲外である行政書士には扱えない**
  （司法書士の独占業務）。財産目録に不動産を記載することはできるが、
  登記手続き自体・登記原因証明情報の作成は対象外とする
- **相続税の申告書作成は税理士の独占業務**である。本モジュールが相続税
  申告の「期限」を計算・リマインドすることと、申告書の作成・税額計算は
  別物であり、期限の見える化に留める
- **紛争性がある場合の代理交渉・遺留分侵害額請求の代理は弁護士の
  独占業務**である。遺留分を侵害している可能性があることの機械的な
  目安表示（FR-S3.4）は行うが、実際の請求の意思表示・交渉・訴訟対応は
  対象外とする
- 以上を踏まえ、本モジュールの結果・生成書類には、他モジュール以上に
  「この機能で対応できる範囲」と「対応できない範囲・専門家への相談を
  要する範囲」を明示する文言を必ず含める設計とする（NFR-S1）

## 2. 用語集

| 用語 | 説明 |
|---|---|
| 法定相続人 | 民法の規定により相続人となる者（配偶者・子・直系尊属・兄弟姉妹等） |
| 法定相続分 | 民法900条・901条が定める、法定相続人各自の取り分の割合 |
| 代襲相続 | 本来の相続人が相続開始以前に死亡・欠格・廃除により相続権を失った場合、その者の子（直系卑属、または兄弟姉妹の場合は甥姪）が代わって相続すること（887条2項・3項、889条2項） |
| 再代襲 | 子の代襲相続において、代襲者（孫）もさらに死亡等している場合、その子（ひ孫）へとさらに代襲が続くこと。兄弟姉妹の代襲（甥姪）には再代襲は生じない |
| 相続放棄 | 家庭裁判所への申述により、相続人としての地位を初めから有しなかったものとみなす手続き（民法939条）。代襲相続の原因にはならない |
| 熟慮期間 | 相続放棄・限定承認をするかどうかを検討できる期間。自己のために相続の開始があったことを知った時から3ヶ月（民法915条1項） |
| 遺留分 | 一定の法定相続人（兄弟姉妹を除く）に法律上保障される最低限の取り分 |
| 遺留分侵害額請求 | 遺留分を侵害する遺贈・贈与を受けた者に対し、遺留分侵害額に相当する金銭の支払いを請求すること（民法1046条） |
| 自筆証書遺言 | 遺言者が全文・日付・氏名を自書し押印する遺言方式（民法968条）。財産目録部分は自書不要（方式緩和） |
| 財産目録 | 相続財産（不動産・預貯金・有価証券等）の一覧 |
| 争いのない相続 | 相続人全員の間で遺産分割の方針に実質的な対立がない状態。本モジュールが対応する前提条件（1.3節） |

## 3. 想定利用者・利用シーン

- 主利用者: 発注者本人（行政書士登録後、相続関連業務の依頼を受けた際に
  使用）
- 想定シーン: 依頼者（相続人の一人であることが多い）から相続手続きの
  相談を受ける → 争いの有無をヒアリングし、争いがない場合のみ本モジュール
  の対象とする → 家族構成を入力し法定相続人・法定相続分を試算 →
  相続人全員に試算結果を共有し、必要に応じて戸籍謄本等で裏付けを取る →
  財産目録を作成 → 相続人間の合意内容を入力し遺産分割協議書サマリーを
  生成 → （遺言書作成支援の場合は）自筆証書遺言の文案を生成し、方式
  要件の説明とともに交付 → 相続放棄・相続税申告等の期限をリマインド

## 4. 機能要件

### 4.1 法定相続人・法定相続分の自動計算

| ID | 内容 | 備考 |
|---|---|---|
| FR-S1.1 | 家族構成（配偶者の有無・子・直系尊属・兄弟姉妹の各情報）を入力として受け取り、民法900条・901条の規定に基づき法定相続人一覧・法定相続分を計算できること | 配偶者と子／配偶者と直系尊属／配偶者と兄弟姉妹／血族相続人なし（配偶者のみ）／配偶者なしの各パターンに対応する |
| FR-S1.2 | 子の代襲相続（孫、さらに死亡している場合はひ孫…と続く再代襲）に対応できること | 民法887条2項・3項 |
| FR-S1.3 | 兄弟姉妹の代襲相続（甥・姪の1世代のみ。再代襲は生じない）に対応できること | 民法889条2項（887条3項は準用されない点に注意） |
| FR-S1.4 | 相続放棄をした者は代襲相続の原因にならないこと（本人・その系統ともに相続人から除外され、下の代には引き継がれない）を計算に反映できること | 民法939条。欠格・廃除は代襲原因になる点と区別して扱う |
| FR-S1.5 | 半血の兄弟姉妹（父母の一方のみを同じくする）の相続分が、全血の兄弟姉妹の1/2になることを計算に反映できること | 民法900条4号ただし書 |
| FR-S1.6 | 直系尊属が相続人になる場合、親等の近い者（父母）を優先し、親等の異なる者が同時に相続人になることはないことを計算に反映できること | 直系尊属には代襲相続の概念はなく、単に近親者が優先する点に注意 |
| FR-S1.7 | 配偶者・血族相続人のいずれも存在しない（相続人不存在）パターンを検出し、相続財産清算人選任等の家庭裁判所手続きが必要になる可能性が高い旨、弁護士への相談を促す警告を出せること | 1.3節 |
| FR-S1.8 | 同時死亡の推定（民法32条の2）・半血兄弟姉妹の判定・養子縁組の有無・内縁関係の扱い等、入力情報の正確性そのものは機械的に検証できない事項について、結果に必ず人手確認を促す警告を含めること | 判定ロジック自体は機械的だが、入力の正確性は戸籍謄本等の一次資料でしか担保できないため |
| FR-S1.9 | 計算結果には、「入力情報に基づく試算であり、確定的な相続人確定には戸籍謄本等の収集・確認が必要である」旨の定型注記を必ず含めること | 既存モジュールの一次スクリーニング注記（`GIJINKOKU_SCREENING_NOTICE`等）と同じ考え方 |

### 4.2 財産目録・遺産分割協議書の生成

| ID | 内容 | 備考 |
|---|---|---|
| FR-S2.1 | 財産（不動産・預貯金・有価証券・自動車・その他）の一覧を入力として受け取り、財産目録をdocxで生成できること | 概算評価額は任意入力とする |
| FR-S2.2 | 法定相続人・法定相続分の計算結果と財産目録を組み合わせ、遺産分割協議書のサマリー（署名・実印押印欄相当を含む）をdocxで生成できること | |
| FR-S2.3 | 相続人間で既に合意済みの分割案（どの財産を誰が取得するか）を入力として受け取り、協議書に反映できること | 合意内容自体の公平性・妥当性は判定しない。あくまで入力された合意の書面化に徹する |
| FR-S2.4 | 生成書類には、「正式な提出様式ではないこと」「相続人全員の実印・印鑑証明書の添付等、最終的な体裁は個別に確認すること」を明記すること | コアの`buildDisclaimerParagraph`を再利用しつつ、本モジュール専用の追加注記を付す |
| FR-S2.5 | `hasDisputeAmongHeirs`（争いの兆候フラグ）が真の案件では、協議書生成の前後で「争いがある場合の遺産分割協議書作成・交渉は行政書士の業務範囲外であり、弁護士に相談する必要がある」旨の警告を強調表示すること | 1.3節を機能レベルで担保する重要項目 |

### 4.3 自筆証書遺言 作成支援

| ID | 内容 | 備考 |
|---|---|---|
| FR-S3.1 | 自筆証書遺言の文案を、遺言者本人が自書すべき本文部分と、自書を要しない財産目録部分（方式緩和により自書不要だが署名押印は必要）を区別して出力できること | 民法968条2項 |
| FR-S3.2 | 出力文案には、「本文は必ず遺言者本人が自書し、日付・氏名を自書のうえ押印すること。代筆・パソコン作成した本文部分は無効になる」旨の注記を含めること | 方式違反は遺言全体の無効原因になるため、他の注記より強く明示する |
| FR-S3.3 | 出力文案には、法務局における自筆証書遺言書保管制度の利用を検討するよう案内する文言を含めること | 紛失・改ざん防止、家庭裁判所の検認手続省略のメリットを簡潔に説明する |
| FR-S3.4 | 想定する遺言内容の分配が、各相続人の遺留分（法定相続分の原則1/2。直系尊属のみが相続人の場合は1/3）を下回っていないかの目安を警告として表示できること | 遺留分侵害の該当性を確定判定するものではなく、注意喚起に留める（機械的な目安計算であり、最終判断は専門家に委ねる） |

### 4.4 相続手続き期限リマインド

| ID | 内容 | 備考 |
|---|---|---|
| FR-S4.1 | 相続放棄の期限（自己のために相続の開始があったことを知った時から3ヶ月）を計算し、既存のリマインド表示ロジックに統合できること | 民法915条1項 |
| FR-S4.2 | 相続税の申告・納付期限（相続の開始があったことを知った日の翌日から10ヶ月）を計算できること | 相続税法27条・33条 |
| FR-S4.3 | 遺留分侵害額請求の期間制限（知った時から1年の消滅時効、相続開始から10年の除斥期間の両方）を計算できること | 民法1048条 |
| FR-S4.4 | 各リマインドのラベルには、対応する実際の手続き（申述書作成・税務申告書作成・請求の意思表示等）を担当すべき専門家（相続放棄申述書の作成＝弁護士・司法書士、相続税申告＝税理士、遺留分侵害額請求の代理＝弁護士）を明記すること | 本モジュールが提供するのは期限の「見える化」までであることを明確にする（1.3節） |
| FR-S4.5 | 死亡日と「相続の開始を知った日」が異なる場合（疎遠な親族の死亡を後日知った等）に対応するため、両者を別々に入力できること | 死亡日は相続税申告期限の起算にも間接的に関わるため（相続税法上は「知った日」が正式な起算点）、両フィールドを明確に区別する |

### 4.5 非機能要件

| ID | 内容 |
|---|---|
| NFR-S1 | 争いの有無・遺留分侵害の該当性・同時死亡の推定・欠格事由該当性等、法的評価を要する事項は自動判定せず、必ず人手確認を促す警告を出すこと（既存モジュールの`seijitsusei.js`〈建設業〉・`kanrensei.js`〈技人国〉と同じ設計思想を継承する） |
| NFR-S2 | 相続人・被相続人のマイナンバー（個人番号）を、入力データモデル・永続化ファイル・docx出力のいずれにも含めないこと。本人確認書類の写し等のバイナリファイル管理も本モジュールの対象外とする |
| NFR-S3 | 氏名等の相続人個人情報は必要最小限とし、相続分計算に必須ではない機微情報（口座番号の全桁・旅券番号等）は入力データモデルに含めないこと |
| NFR-S4 | 既存NFR-1〜7・NFR-C1〜C3を継承する（特にNFR-4: 外部送信禁止は、相続人・被相続人の個人情報を扱う本モジュールで最も重要度が高い） |
| NFR-S5 | 法定相続分の計算は浮動小数点演算による丸め誤差を避け、分数（または整数比）で内部処理し、相続分の合計が必ず1になることを自己検証できる設計とすること |

### 4.6 スコープ外（本フェーズで対応しないこと）

- 相続放棄申述書そのものの作成（家庭裁判所提出書類のため弁護士・司法書士の職域。1.3節）
- 相続税申告書の作成・税額計算（税理士の独占業務。1.3節）
- 相続登記・不動産の名義変更手続き（司法書士の独占業務。相続登記義務化〈2024年4月施行〉に伴う期限管理も本フェーズは対象外）
- 遺産分割調停・審判の申立書作成、遺留分侵害額請求の交渉・訴訟代理（弁護士の独占業務。弁護士法72条）
- 公正証書遺言の作成手続き（公証人役場とのやり取り自体）。文案作成の支援は対象とするが、公証人との調整代行は対象外
- 相続人間に争いがある場合の調整・仲介・代理交渉
- 数次相続（遺産分割前に相続人自身が死亡し、その相続人がさらに承継するケース）の自動計算。法的性質が代襲相続と異なるため、`calcLegalHeirs`は代襲相続のみを対象とする
- 相続財産の評価額算定（不動産の相続税評価額の計算等）
- 相続人・被相続人のマイナンバー等の機微個人情報の管理（NFR-S2）
- Web一覧表示への対応（`src/web/`の拡張。他モジュール同様、本フェーズは対象外）

## 5. 受け入れ基準

1. `npm test` が既存分＋新規追加分すべて成功すること
2. 既存モジュール（建設業許可・古物商許可・産廃・民泊・在留資格・
   下請けポータル）の出力・挙動が変化しないこと（回帰テスト）
3. 代表的な家族構成パターン（配偶者と子／配偶者と直系尊属／配偶者と
   兄弟姉妹／子のみ／代襲相続あり〈孫・再代襲を含む〉／兄弟姉妹の代襲
   〈甥姪〉／半血兄弟姉妹あり／相続放棄ありのケース／相続人不存在）の
   それぞれについて、`calcLegalHeirs`が民法900条・901条の規定通りの
   結果（相続分の合計が必ず1になることを含む）を返すこと
4. ダミーデータから、財産目録・遺産分割協議書サマリー・自筆証書遺言
   文案のdocxが生成できること
5. 相続放棄・相続税申告・遺留分侵害額請求の期限が、死亡日（または
   「知った日」）を起点として正しく計算されること
6. `hasDisputeAmongHeirs`が真の案件で、協議書生成に際して職域外である
   旨の警告が表示されること
7. 生成される計算結果・書類のいずれにも、マイナンバー等の機微個人情報
   フィールドが存在しないこと（NFR-S2の型レベルでの担保を確認する）

## 6. 前提条件・依存事項

- 実装前に、民法900条・901条・887条・889条・915条・932条・939条・
  968条・1042条〜1048条の条文をe-Gov法令検索で確認すること
- 相続税法27条・33条（申告・納付期限）の条文を確認すること
- 行政書士が対応できる相続業務の範囲について、日本行政書士会連合会等の
  公式見解・信頼できる行政書士事務所の解説記事で改めて確認すること
  （本要件定義書7章に一次調査結果を記載しているが、実装直前に再確認する）
- 法務局の自筆証書遺言書保管制度の最新の運用（手数料・様式）を確認すること
- 実際に相続関連の依頼を受注する前に、発注者自身が「争いの有無」を
  適切に見極める判断力（ヒアリング能力）を備えているか、必要に応じて
  弁護士等との連携体制を事前に確保しておくこと（1.3節の運用面での前提）
