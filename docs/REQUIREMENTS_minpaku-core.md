# 要件定義書 — 住宅宿泊事業（民泊）届出モジュール

version: 0.1 / 2026-09 作成
対象: kensetsu-kyoka-toolkit の拡張（許認可自動化コアの4例目としての実装）

## 0. 本書の位置づけ

本書は、許認可自動化コア（`src/core/`。`docs/DESIGN_kobutsu-core.md`）の
上に「住宅宿泊事業（民泊）届出」アドオンを追加する開発の要件定義書。
コア自体の設計は `docs/DESIGN_kobutsu-core.md` を参照。開発環境構築・
コーディング規約・Git運用は既存の `docs/DEVELOPMENT_GUIDE.md` を適用する。

## 1. プロジェクト概要

### 1.1 背景

住宅宿泊事業法（民泊新法）に基づく届出は、これまで対象としてきた
建設業許可・古物商許可・産業廃棄物収集運搬業許可と異なり、**許可制ではなく
届出制**である。公安委員会・都道府県による裁量的な審査を経ずに、
形式が整った書類が受理されれば事業を開始できるため、要件判定エンジンの
役割は「欠格事由に該当しないことの確認」と「必要書類がすべて揃っている
ことのチェックリスト化」が中心になり、建設業許可のような複雑な合否
判定ロジックは基本的に不要になる。

一方で、届出後は**2ヶ月ごとの定期報告**（宿泊日数・宿泊者数等の実績報告）
という、建設業許可の「5年に1度の更新」・古物商許可の「変更が生じた
ときだけ」とは異なる、**一定間隔で繰り返し発生するリマインド**が必要になる。
この「定期・反復型」のリマインドパターンを実装することで、コアの
リマインド・レジストリ（`registerScheduleFn`）が3種類の全く異なる
リマインド方式（有効期限型・変更トリガー型・定期反復型）に対応できる
汎用設計であることを検証する。

民泊は市場としての伸びも見込め、集客の観点でも柱（B）の中で優先度の
高い候補になり得る。

### 1.2 目的

1. 欠格事由・必要書類の充足チェックを実装する（許可判定ではなく
   「届出の準備が整っているか」の確認という位置づけ）
2. 届出書のサマリーをdocxで生成する
3. 届出後の定期報告（2ヶ月ごと）の次回期限を自動計算し、コアの
   リマインドエンジンに登録する

### 1.3 重要な制約

- 住宅宿泊事業法上、報酬を得て官公署に提出する届出書類を作成する行為は
  行政書士の独占業務に含まれる。行政書士登録が完了するまで、本ツールを
  使って有償で書類作成・提出代理を行うことはできない（既存原則を継承）
- 民泊制度運営システム（国土交通省・観光庁・厚生労働省が共同運営する
  電子申請システム）への実際の電子申請・入力代行の自動化は本フェーズの
  対象外とする（4.5節）。本ツールが行うのは、届出前の準備段階の
  書類サマリー生成とチェックリスト化に留める
- 定期報告の期限計算は「参考情報」であり、正式な提出期限・提出方法は
  必ず民泊制度運営システムの公式案内で確認すること（8章の日付ルールは
  実装前に一次資料で確認すること）

## 2. 用語集

| 用語 | 説明 |
|---|---|
| 住宅宿泊事業（民泊） | 住宅宿泊事業法に基づき、旅館業法の許可を得ずに住宅を宿泊施設として提供する事業。都道府県知事等への届出制 |
| 住宅宿泊管理業者 | 家主不在型の場合、届出住宅の管理を委託する義務がある登録業者 |
| 民泊制度運営システム | 届出・報告の電子申請を行う国のシステム |
| 定期報告 | 届出後、2ヶ月ごとに宿泊日数・宿泊者数等の実績を届出先に報告する義務 |
| 消防法令適合通知書 | 消防署が発行する、消防法令に適合していることの通知書。届出の添付書類の一つ |

## 3. 想定利用者・利用シーン

既存モジュールと同じ利用形態（発注者本人が行政書士登録後、CLI/
スクリプト操作で使用）。想定シーンとして、民泊を始めたい個人の住宅
所有者から相談を受け、①欠格事由・必要書類のチェック→②届出書サマリー
の生成→③届出後の定期報告リマインドの設定、という流れを想定する。

## 4. 機能要件

### 4.1 民泊 要件・書類充足チェック

| ID | 内容 | 備考 |
|---|---|---|
| FR-M1.1 | 欠格事由（**住宅宿泊事業法第4条**。心身の故障・破産・事業廃止命令・拘禁刑等または本法/旅館業法違反の罰金刑から3年未満、暴力団関係者から5年未満 等、8号立て）を判定できること | e-Gov法令検索で原文確認済み（2026年9月）。**当初案の「第5条」は誤り（第5条は宿泊者の衛生確保に関する条文であり欠格事由とは無関係）。正しくは第4条**。また期間も「一律5年」ではなく、暴力団関係（第5号）のみ5年、その他（第1〜4号: 心身故障・破産・事業廃止命令・拘禁刑または罰金刑）は3年である点に注意。詳細はDESIGN_minpaku-core.md 3章のMinpakuKekkakuInput参照 |
| FR-M1.2 | 家主居住型／家主不在型の別を入力として受け取り、家主不在型の場合は住宅宿泊管理業者への委託が必須である旨の警告を出せること（委託先の選定支援自体は対象外。4.5節） | |
| FR-M1.3 | 必要書類（登記事項証明書・図面・消防法令適合通知書・誓約書 等）について、入力データ上「取得済み／未取得」のチェックリストとして管理し、未取得の書類がある場合に一覧で警告できること | 建設業許可のような合否判定ではなく、届出実務でよくある「書類の出し漏れ」を防ぐためのチェックリスト機能という位置づけ（要件判定エンジンというより準備状況チェッカーに近い） |
| FR-M1.4 | 外国語で発行された書類がある場合、日本語訳の添付が必要である旨の注記を出せること | |

### 4.3 民泊 定期報告リマインド（コアへの登録）

| ID | 内容 | 備考 |
|---|---|---|
| FR-M3.1 | 届出（事業開始）以降に到来する定期報告の「次回期限」を計算できること | **一次資料確認により「届出日起算で2ヶ月ごと」という当初案は誤りと判明**。住宅宿泊事業法施行規則第12条第2項（e-Gov法令検索で原文確認済み・2026年9月）により、報告は暦年基準で毎年2・4・6・8・10・12月の15日までに、それぞれの月の前2ヶ月分をまとめて報告する固定6区分制。つまり「次回期限」は起点日に依存せず、常に直近の2/15・4/15・6/15・8/15・10/15・12/15のうち今日以降で最初に到来する日になる |
| FR-M3.2 | 定期報告の次回期限は、時間の経過とともに自動的に次の固定日へ進むこと（繰り返しのリマインドであるため、1回きりの期限計算では不十分） | **一次資料確認により、当初案の「報告実績日を記録すると再計算される」という設計は撤回**。施行規則第12条第2項の期限は暦日固定制であり報告実績に依存しないため、専用の記録関数は不要。DESIGN_minpaku-core.md 4.3節のとおり、スケジュール計算関数が「本日」を基準に暦日テーブルを参照するだけで自動的に次の固定日へ進む |
| FR-M3.3 | 定期報告のリマインドは、既存のリマインド一覧（`bucketizeAlerts`の5区分）にそのまま統合され、他の許可種別のリマインドと合わせて一覧表示できること | コアとの統合確認 |

### 4.4 インテイク

既存と同様、CLI/スクリプト操作を前提とする。

### 4.5 スコープ外（本フェーズで対応しないこと）

- 民泊制度運営システムへの電子申請・入力代行の自動化
- 住宅宿泊管理業者の選定支援・比較
- 消防法令適合通知書の取得代行（消防署とのやり取りそのもの）
- 複数物件を1事業者が運営する場合の一括管理（本フェーズは1物件単位）
- 家主不在型における管理業務の実施状況モニタリング

### 4.6 非機能要件

既存NFR-1〜7・NFR-C1〜C3を継承する。

## 5. 受け入れ基準

1. `npm test` が既存分＋新規追加分すべて成功すること
2. 既存モジュール（建設業許可・古物商許可・産廃）の出力・挙動が
   変化しないこと（回帰テスト）
3. 民泊について、ダミーデータから欠格事由・必要書類チェックリストの
   確認、および2様式（届出書・誓約書）のdocxサマリー生成ができること
4. 届出済みの民泊クライアントについて、暦日固定（毎年2/4/6/8/10/12月
   15日）のうち今日以降で最初に到来する日が、次回の定期報告期限として
   正しく算出されること（**当初想定していた「報告実績日を記録すると
   2ヶ月後に再計算される」という仕様は、一次資料確認によりFR-M3.1の
   とおり暦日固定制であると判明したため撤回**）
5. 定期報告のリマインドが、既存のリマインド一覧の区分（期限超過／
   1ヶ月以内／1〜3ヶ月／3〜6ヶ月／6ヶ月超）に正しく分類されること

## 6. 前提条件・依存事項

- 実際に活動予定の都道府県が確定していること
- 住宅宿泊事業法第4条の欠格事由、および定期報告の正確な期限ルール
  （報告対象期間の区切り方・提出期限の日数）を一次資料
  （民泊制度運営システムの公式案内、観光庁の通知等）で確認すること
  → **2026年9月に確認済み**。欠格事由は第4条（第5条ではない）、定期報告は
  施行規則第12条第2項により毎年2/4/6/8/10/12月15日の固定6区分制。
  上記FR-M1.1・FR-M3.1に反映済み
- 対象様式（届出書・誓約書）の正式レイアウトを発注者から共有を受けること
