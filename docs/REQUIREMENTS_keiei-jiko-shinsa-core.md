# 要件定義書 — 経営事項審査（経審）申請支援モジュール

version: 0.1 / 2026-09 作成
対象: kensetsu-kyoka-toolkit の拡張（許認可自動化コアの6例目としての実装）

## 0. 本書の位置づけ

本書は、許認可自動化コア（`src/core/`。`docs/DESIGN_kobutsu-core.md`）の
上に「経営事項審査（経審）申請支援」アドオンを追加する開発の要件定義書。
コア自体の設計は `docs/DESIGN_kobutsu-core.md` を参照。開発環境構築・
コーディング規約・Git運用は既存の `docs/DEVELOPMENT_GUIDE.md` を適用する。

本モジュールは、古物商許可・産業廃棄物収集運搬業許可・民泊届出・
在留資格支援のような「新しい許可種別への横展開」ではなく、**既存の
建設業許可クライアントへのクロスセル**という位置づけが他モジュールと
異なる。経営事項審査は建設業許可を受けていることが前提条件であり、
本モジュールは独立した許可種別アドオンでありながら、既存の
`licenseCategory: "construction"` の `LicenseEntry` と同一クライアント
レコード内で連携する設計を強く意識する（4.4節・8章参照）。

## 1. プロジェクト概要

### 1.1 背景

経営事項審査（経審）は、国・地方公共団体等が発注する公共工事（500万円
以上、建築一式工事は1,500万円以上が目安）を直接請け負おうとする建設業者が
必ず受けなければならない審査であり、建設業許可を受けていることが受審の
大前提となる。既存の建設業許可クライアントの中には、将来的に公共工事の
入札参加を目指す事業者が一定数含まれると見込まれ、建設業許可の更新
リマインドを既に管理している顧客基盤に対し、経審の受審支援を追加提案
できることは自然なクロスセルの機会になる。

一方で、経審には他モジュールにない新しい複雑性がある。①評価項目
（X1完成工事高・X2自己資本額及び利払前利益・Y経営状況・Z技術職員数及び
元請完成工事高・W社会性等）が多岐にわたり、財務諸表の分析（Y）は
登録経営状況分析機関という外部の専門機関への申請が必要になる、②結果の
有効期間が「審査基準日（直前の決算日）から1年7ヶ月」という固定日数ではなく
基準日を起点にした期間になる、③公共工事の入札参加資格を継続的に維持する
ためには、この1年7ヶ月の有効期間を切らさないよう**毎年**（正確には
決算のたびに）受審し続ける必要がある、という3点である。これは既存の
「5年に1度の更新」（建設業許可・産廃許可）とも「変更が生じた時だけ」
（古物商許可）とも「一定間隔で機械的に繰り返す」（民泊の2ヶ月ごと定期報告）
とも異なる、**「決算という会社ごとに固定された年次イベントを起点に、
翌年も・その翌年も、途切れなく繰り返し受審する」年次反復型**の新しい
リマインドパターンであり、これを実証することも本開発の目的の一つとする。

### 1.2 目的

1. 経審の前提条件確認（建設業許可の保有・決算変更届の提出状況）と、
   評価項目5要素（X1・X2・Y・Z・W）の入力データが申請に必要な形式を
   満たしているかの確認（点数計算そのものは対象外。1.3節）を実装する
2. 経営規模等評価申請書・経営状況分析申請書の記載内容サマリー、および
   必要書類チェックリストをdocxで生成する
3. 経審の有効期限（審査基準日から1年7ヶ月）を管理し、有効期間を切らさず
   毎年受審できるよう、年次反復型のリマインドをコアのリマインドエンジンに
   登録する
4. 既存の建設業許可クライアントレコードに、経審の`LicenseEntry`
   （`licenseCategory: "keiei-jiko-shinsa"`）を追加できる形で連携する

### 1.3 重要な制約（法的前提）

- 建設業法上、報酬を得て官公署に提出する経営規模等評価申請書類を作成する
  行為は行政書士の独占業務に含まれる。行政書士登録が完了するまで、本ツール
  を使って有償で書類作成・提出代理を行うことはできない（既存原則を継承）
- 本システムの判定結果・生成書類は一次スクリーニング・下書きであり、
  「経審の点数（総合評定値P点）を保証・算出するもの」ではない。X1〜Wの
  実際の点数計算には国土交通省が定める評点テーブル・算定式（毎年度
  改定される可能性がある）を用いる必要があり、その精密な再現は本フェーズの
  対象外とする（4.6節）。本モジュールが行うのは、①前提条件・入力データの
  形式的な完備性確認、②申請書類のサマリー生成、③有効期限管理という
  3点に限定する
- Y（経営状況）の分析は、行政書士本人ではなく国土交通大臣の登録を受けた
  「登録経営状況分析機関」が行う法定の外部手続である。本ツールはY分析の
  申請要否・申請状況の管理チェックリストを提供するに留まり、財務分析
  そのものを代行・自動計算しない
- 経審の結果（総合評定値・各評点）は公表情報である（発注者が入札参加
  資格者名簿等で公開するのが通例）という制度の性質上、他モジュール以上に
  「本ツールの出力はあくまで申請準備の下書きであり、実際の評点は審査行政庁
  ・登録経営状況分析機関の審査結果による」旨を全出力に明記すること

## 2. 用語集

| 用語 | 説明 |
|---|---|
| 経営事項審査（経審） | 公共工事の入札参加を希望する建設業者について、経営状況・経営規模・技術力・社会性等を数値評価する審査。建設業法第27条の23に基づく |
| 総合評定値（P点） | X1・X2・Y・Z・Wの5評点を加重平均して算出する経審の最終評点。入札参加資格審査（指名願い）の格付けの基礎になる |
| X1（完成工事高評点） | 直前2年または3年の完成工事高の平均値を業種別に評価する評点 |
| X2（経営規模評点） | 自己資本額（貸借対照表の純資産合計）と利払前利益の平均から算出する評点 |
| Y（経営状況評点） | 負債抵抗力・収益性・財務健全性等、財務諸表から算出する複数指標の分析評点。登録経営状況分析機関への申請が必要 |
| Z（技術力評点） | 技術職員数（保有資格別）と元請完成工事高の平均から算出する評点 |
| W（社会性等評点） | 社会保険加入状況・営業継続年数・防災協定の締結・法令遵守状況（指名停止処分の有無等）等を評価する評点 |
| 審査基準日 | 経審の評価基準となる日。直前の事業年度終了日（決算日）を指す |
| 決算変更届 | 建設業許可業者が毎事業年度終了後4ヶ月以内に提出する届出。経審申請の前提書類でもある |
| 登録経営状況分析機関 | Yの財務分析を行う、国土交通大臣の登録を受けた民間機関（複数存在し、事業者が選択して申請する） |
| 経営規模等評価申請 | X1・X2・Z・Wの評価を受けるための、許可行政庁（都道府県等）への申請 |
| 経営規模等評価結果通知書 | 経営規模等評価申請の結果として交付される、X1・X2・Z・W及び総合評定値Pを記載した通知書 |
| 入札参加資格審査（指名願い） | 発注者ごとに行う、公共工事の入札に参加するための資格審査。有効な経審結果の保有が前提条件になる |

## 3. 想定利用者・利用シーン

既存モジュールと同じ利用形態（発注者本人が行政書士登録後、CLI/
スクリプト操作で使用）。想定シーンは他モジュールと異なり、新規の
顧客獲得ではなく**既存クライアントへの追加提案**が中心になる。

- 建設業許可の更新リマインドで管理している既存クライアントのうち、
  公共工事の受注意向があるクライアントに対し、経審の受審支援を提案する
- 提案受諾後、既存の`ClientRecord`（当該クライアントの建設業許可
  `LicenseEntry`を含む）に、経審の`LicenseEntry`
  （`licenseCategory: "keiei-jiko-shinsa"`）を追加する
- 前提条件（建設業許可の保有・決算変更届の提出状況）を確認 →
  評価項目5要素の入力データの完備性を確認 → 申請書類サマリーを生成 →
  発注者本人が内容を確認・修正 → 正式様式へ転記し、経営状況分析機関・
  許可行政庁へ提出、という流れの中で①前提条件・入力確認と②書類下書き
  生成を担う
- 初回受審後は、毎年の決算のたびに「そろそろ次の経審を受ける時期です」
  というリマインドを受け取り、有効期間を切らさず受審し続けられるよう
  支援する（1.1節・4.3節）

## 4. 機能要件

### 4.1 経審 前提条件・要件確認

| ID | 内容 | 備考 |
|---|---|---|
| FR-KJ1.1 | 対象クライアントの`ClientRecord`に`licenseCategory: "construction"`の`LicenseEntry`が存在することを確認できること。存在しない場合はエラー扱い（経審は建設業許可を受けていることが法定の前提条件であるため。1.1節） | 他モジュールには無い「同一クライアントレコード内の別ライセンスとの連携チェック」。設計書4章参照 |
| FR-KJ1.2 | 直近決算分の決算変更届が提出済みであるかを入力として受け取り、未提出の場合は「経審申請の前提書類が未整備」である旨の警告を出せること | 決算変更届自体の生成・提出は既存の建設業許可機能（コアの`kessan-henko`アラート。`docs/DESIGN_kobutsu-core.md` 5.3節）の対象であり、本モジュールは提出状況の確認のみを行う |
| FR-KJ1.3 | 経審を受ける業種区分（建設業許可を受けている業種の範囲内）を入力として受け取り、1業種以上選択されていることを確認できること | 業種を追加する場合の複雑な扱い（許可を受けていない業種を経審だけ先行させる特殊ケース等）は対象外（4.6節） |
| FR-KJ1.4 | X1（完成工事高）・X2（自己資本額・利払前利益）・Z（技術職員数・元請完成工事高）・W（社会性等）の入力データについて、必須項目が入力されているかの形式的な完備性チェックができること。実際の点数（評点）計算は行わないこと | 評点テーブル・算定式は国土交通省の告示に基づき毎年度改定され得るため、精密な再現は対象外とする（1.3節） |
| FR-KJ1.5 | Y（経営状況）について、登録経営状況分析機関への申請要否・申請状況（未申請／申請中／結果受領済み）をステータスとして管理できること。財務分析自体は行わないこと | 経営規模等評価申請にはYの分析結果が必要なため、申請状況が「結果受領済み」でない場合は警告を出す（FR-KJ1.6） |
| FR-KJ1.6 | 上記をまとめて、経審申請の準備状況を人間可読なテキストレポートに整形できること（建設業許可のような合否判定ではなく、産廃・民泊と同様「準備状況の可視化」が中心） | コアの`formatChecksSection`を再利用 |

### 4.3 経審 有効期限リマインド（コアへの登録・年次反復型）

| ID | 内容 | 備考 |
|---|---|---|
| FR-KJ3.1 | 直近の経審の審査基準日（決算日）を入力とし、その有効期限（審査基準日から1年7ヶ月）を算出できること | 設計書4.3節参照。有効期限内に次回の経審結果を受領できないと、入札参加資格を維持できなくなる（1.1節） |
| FR-KJ3.2 | 直近の審査基準日を起点に、翌年の審査基準日（次回決算日）を推定し、①次回決算に向けた決算変更届の提出期限、②経審再受審の推奨申請時期、③現行の経審結果の有効期限（絶対に切らしてはならない期限）の3種類のリマインドを算出し、コアのスケジュール・レジストリ（`registerScheduleFn("keiei-jiko-shinsa", ...)`）に登録できること | 建設業許可の「満了180日前／60日前／30日前」という3段階の考え方（`docs/DESIGN_kobutsu-core.md` 5.6節）と、民泊の「直近の実績日を起点に動的計算する」という考え方（`docs/DESIGN_minpaku-core.md` 4.3節）を組み合わせた、年次反復型の新しいパターンとして設計する（設計書4.3節） |
| FR-KJ3.3 | 新しい経審結果を受領したことを記録すると、審査基準日が更新され、次回サイクルのリマインドが再計算されること（繰り返しのリマインドであるため、1回きりの期限計算では不十分。民泊のFR-M3.2と同じ考え方） | コアのリマインド・レジストリに「直近の審査基準日」を入力として渡せる設計を利用する |
| FR-KJ3.4 | 経審のリマインドは、既存のリマインド一覧（`bucketizeAlerts`の5区分）にそのまま統合され、建設業許可の更新リマインド等、他の許可種別のリマインドと合わせて一覧表示できること | コアとの統合確認 |

### 4.5 インテイク

既存と同様、CLI/スクリプト操作を前提とする（Webフォーム対応は対象外）。

### 4.6 スコープ外（本フェーズで対応しないこと）

- X1・X2・Y・Z・Wの実際の点数（評点）計算・総合評定値（P点）の算出
  （国土交通省の評点テーブル・算定式の精密な再現。1.3節）
- 登録経営状況分析機関の選定支援・比較
- 経審申請・決算変更届の電子申請システムへの入力代行の自動化
- 建設業許可を受けていない業種を対象にした経審申請への対応
- 特定建設業・一般建設業の別による申請内容の差異の詳細対応
- 個人事業主（法人化していない建設業者）の経審固有の論点への対応
- 入札参加資格審査（指名願い）そのものの申請支援（経審の"次"の手続であり、発注者ごとに手続が異なるため対象外）

### 4.7 非機能要件

既存NFR-1〜7・NFR-C1〜C3（`docs/DESIGN_kobutsu-core.md`）を継承する。
追加で、経審の評価データは他モジュール以上に会社の財務内容そのもの
（自己資本額・完成工事高・利益額等）を扱うため、NFR-4（外部送信禁止）
の遵守を特に強調する。

## 5. 受け入れ基準

1. `npm test` が既存分＋新規追加分すべて成功すること
2. 既存モジュール（建設業許可・古物商許可・産廃・民泊・在留資格支援）の
   出力・挙動が変化しないこと（回帰テスト）
3. 経審について、ダミーデータから前提条件確認（建設業許可の保有・
   決算変更届の提出状況）、評価項目5要素の入力完備性チェック、および
   2様式（経営規模等評価申請書・経営状況分析申請書）＋チェックリストの
   docxサマリー生成ができること
4. 建設業許可の既存クライアントに経審の`LicenseEntry`を追加した際、
   同一クライアントレコード内の建設業許可の許可業種が正しく参照でき、
   リマインド一覧に両方の許可種別が区別して表示されること
5. 経審の審査基準日を1件記録すると、有効期限（基準日から1年7ヶ月）と
   翌年の決算変更届提出期限・再受審推奨時期が正しく算出され、新しい
   審査基準日を記録すると次回サイクルの期限が再計算されること
6. 建設業許可を持たないクライアントに対して経審の要件確認を実行した場合、
   前提条件エラーとして扱われること（FR-KJ1.1）

## 6. 前提条件・依存事項

- 対象クライアントが既に建設業許可（`licenseCategory: "construction"`）を
  保有していること
- 建設業法第27条の23〜第27条の29、および国土交通省の関連告示・通知
  （経営事項審査の項目及び基準を定める件 等）を一次資料として、評価項目の
  正確な区分・有効期間のルールを実装前に確認すること
- 対象様式（経営規模等評価申請書・経営状況分析申請書）の正式レイアウトを
  発注者から共有を受けること
- 登録経営状況分析機関の選定は発注者・クライアントの判断に委ねる
  （本ツールは申請状況の管理のみを行う。4.6節）
