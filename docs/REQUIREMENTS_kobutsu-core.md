# 要件定義書 — 許認可自動化コア拡張＋古物商許可モジュール

version: 0.2 / 2026-09 修正（実装着手前レビューで8章をe-Gov原文と照合し訂正。0.1からの変更点は末尾の改訂履歴を参照）
対象: kensetsu-kyoka-toolkit の拡張（既存の建設業許可機能に影響を与えないことを前提とした追加開発）

## 0. 本書の位置づけ

本書は「新規ソフトウェア開発提案書（許認可自動化基盤の展開 — 古物商許可モジュール）」を受けて、
外部の開発者に実装を委託するにあたり、実装すべき機能・仕様・制約を明文化したものである。

開発環境構築・コーディング規約・Git運用は、既存の `docs/DEVELOPMENT_GUIDE.md`
（建設業許可分として作成済み）をそのまま適用し、本書では繰り返さない
（同一リポジトリ内での拡張であり、開発体制自体は変わらないため）。
本書と対をなす技術設計書は `docs/DESIGN_kobutsu-core.md`（今回新規作成分）。
既存の `docs/REQUIREMENTS.md`（建設業許可分）・`docs/DESIGN.md`・`docs/adr/`
とあわせて参照すること。

## 1. プロジェクト概要

### 1.1 背景

発注者は行政書士を副業として開業予定であり、建設業許可を旗艦分野とする
kensetsu-kyoka-toolkit（要件判定エンジン・書類自動生成・複数許可対応の
クライアント管理・更新リマインドを実装済み。M1〜M10完了）を運用している。

事業提案の柱の一つである「定型許認可のテンプレート・自動化サービス」は、
本来は建設業許可1種類に限定されるものではない。現状の実装は
`ApplicantProfile` 型・様式生成モジュール・`prefectureRules.js` など設計思想
自体は横展開を意識しているが、実装はすべて建設業許可のドメイン知識に
強く結びついている。

本開発は、①この実装を「許可種別非依存の共通コア＋許可種別ごとの薄い
アドオン」という構造に整理し直すリファクタリングと、②その基盤の汎用性を
実装で検証するためのパイロット第2弾として「古物商許可」モジュールを
新規実装すること、の2つを対象とする。

### 1.2 目的

1. **コア抽出**: `src/eligibility/`・`src/documents/`・`src/reminders/` から
   建設業許可固有のロジックを除いた「許可種別非依存の骨格」を切り出す
2. **古物商許可モジュール**: 切り出したコアの上に、古物商許可の
   ①要件判定（欠格事由・営業所/管理者要件）、②書類生成（許可申請書・
   誓約書・略歴書）、③変更届・書換申請のリマインドを実装する

行政書士本人が行うのは「最終内容の確認・押印・提出」のみに絞り込むという
既存プロダクトの設計思想を、古物商許可でも維持する。

### 1.3 重要な制約（法的前提）

- 古物営業法上、報酬を得て官公署に提出する古物商許可申請書類を作成する
  行為は、行政書士法における行政書士の独占業務に含まれる。行政書士登録が
  完了するまで、本ツールを使って有償で書類作成・提出代理を行うことはできない
  （既存の`docs/REQUIREMENTS.md` 1.3節と同じ制約。許可種別が変わっても
  この制約自体は変わらない）。
- 本システムの判定結果は「申請前の一次スクリーニング」であり、
  「許可が下りることを保証するもの」ではない。UIやドキュメント上の
  文言でもこの前提を誤解させる表現をしないこと（既存原則を継承）。
- 古物営業法第4条（許可の基準）・第13条（管理者）は、2026年9月に
  [e-Gov法令検索の古物営業法本文](https://laws.e-gov.go.jp/law/324AC0000000108)
  （令和7年6月1日施行の現行版）で号立て・文言を確認済みであり、本書8.1・
  8.2節に反映済み（既存プロジェクトが `docs/adr/0009-*.md`・`0010-*.md` で
  取っている「一次資料を確認できない項目は対象外とする」方針と同じ考え方で、
  今回は実装着手前に確認を完了させた）。ただし8.3〜8.5節（記載事項・添付
  書類・届出期限・手数料）は引き続き未確認の二次情報であり、実装着手前に
  同様の確認が必要。また法令は改正されうるため、実装時点で念のため
  再確認すること。

## 2. 用語集

| 用語 | 説明 |
|---|---|

| 古物営業法 | 古物商・古物市場主の営業について定める法律。窓口は警察署、審査機関は都道府県公安委員会 |

| 書換申請 | 許可証の記載事項（氏名・住所等）に変更が生じた場合の申請手続 |
| 変更届出 | 許可証の記載事項以外の変更事項（取り扱う古物の区分の追加等）を届け出る手続 |
| 許認可自動化コア | 建設業許可・古物商許可など、許可種別を問わず再利用できる要件判定・書類生成・リマインドの共通基盤（本開発で新設） |
| ライセンスアドオン | コアの上に載る、特定の許可種別固有のロジック（判定ルール・様式・リマインド方式） |

## 3. 想定利用者・利用シーン

- **主利用者**: 発注者本人（行政書士登録後、自身の業務で使用する）。
  既存の建設業許可機能と同じ利用者・同じ運用形態
- **想定シーン**: 顧客（古物商許可を取得したい個人）から必要情報をヒアリングし、
  本システムに入力 → 要件判定結果を確認 → 書類下書きを生成 →
  発注者本人が内容を確認・修正 → 正式様式へ転記し提出、という流れの中で
  ①要件判定と②書類下書き生成を担う
- 本フェーズでは、既存の建設業許可と同様、顧客が直接システムを操作する
  フォームは対象外とし、発注者本人がデータを入力・実行するCLI/スクリプト
  操作を前提とする（`src/web/` の古物商対応は本フェーズの対象外。6章参照）

### 4.2 古物商許可 要件判定エンジン（新規）

| ID | 内容 | 状態／備考 |
|---|---|---|
| FR-K1.1 | 古物営業法第4条の欠格事由（一号〜十号。十一号は法人申請の場合のみ判定）に該当しないかを判定できること | 号立て・文言は8章参照（2026年9月にe-Gov法令検索の原文で確認済み。第七号の追加・第二号の「拘禁刑」への訂正を含む）。第十一号（法人役員の欠格）は2026年9月に対応済み（`KobutsuOfficerInput`）。今後の法改正に備え、実装時に念のため再確認すること |
| FR-K1.2 | 営業所の実在性・使用権限を確認する入力を受け取り、未確認の場合は要確認の注記を出せること | 建設業許可の `seijitsusei.js`（誠実性・自己申告ベース）と同様、機械的に判定しきれない項目は「必ず人手確認を促す警告」とする |
| FR-K1.3 | 営業所ごとに管理者が選任されていることを判定できること（古物営業法第13条） | 1営業所1管理者を原則とする（建設業許可の専任技術者と類似の「専任性」チェックだが、複数営業所での重複確認は古物商では管理者の常勤性の考え方が異なるため、機械的な重複エラーにはせず注記に留める。要件定義段階での簡易仕様。詳細は設計書で検討）。なお第4条第十号（管理者を選任すると認められないことについて相当な理由がある者）は行政庁の裁量的判断のため単純な入力項目にしにくく、本FR-K1.3で実務上カバーされるものとしFR-K1.1側の欠格事由には含めない（8.1節参照） |
| FR-K1.4 | 未成年者について、営業に関し成年者と同一の行為能力を有する場合の例外規定を判定できること | 古物営業法第4条第九号（8章参照）。例外は「古物商・古物市場主の相続人であり、その法定代理人が欠格事由（一号〜八号・十一号）に該当しない場合」に限定される狭い規定であることをe-Gov原文で確認済み（「法定代理人の許可があれば良い」という一般的な話ではない点に注意） |
| FR-K1.5 | 上記をまとめて総合判定し、未充足理由の一覧を人間可読なテキストレポートに整形できること | 既存の `formatEligibilityReport` と同じパターンを古物商用に用意する（コア側に共通化できる部分があれば共通化を検討。設計書5章参照） |

### 4.4 古物商許可 変更届・書換申請リマインド（新規）

古物商許可には建設業許可のような更新制度（有効期限）がない。その代わり、
許可証記載事項の変更に伴う「書換申請」（変更後14日以内）、記載事項以外の
変更に伴う「変更届出」（事由発生から3日以内）、廃業時の「許可証の返納」
（10日以内）という、期限の起点が「許可日」ではなく「変更・廃業という
出来事の発生日」である点が建設業許可と根本的に異なる。

| ID | 内容 | 備考 |
|---|---|---|
| FR-K3.1 | 古物商許可のクライアントについては、満了日ベースの更新リマインド（建設業許可の`renewal-early-notice`等）を一切生成しないこと | FR-C1.4のプラグイン方式で「リマインドを生成しない」ことも選択できる設計であることの確認を兼ねる |
| FR-K3.2 | 氏名・住所等、許可証記載事項の変更日を入力すると、「書換申請の期限（変更日から14日以内）」を自動計算しリマインドできること | 既存の `daysUntil()` を再利用。計算方法は暦日での単純な日数加算（建設業許可の`addMonthsClamped`のような月単位の丸めは不要） |
| FR-K3.3 | 廃業日を入力すると、「許可証の返納期限（廃業日から10日以内）」を自動計算しリマインドできること | 同上 |
| FR-K3.4 | 記載事項以外の変更（取り扱う古物の区分の追加等）については、「事由発生から3日以内」という期限が非常に短いため、期限までの日数を計算する形のリマインド一覧には含めず、変更内容を入力した時点で即座に「3日以内に変更届が必要です」と警告する、入力時バリデーションとして実装すること | 既存のリマインド・ダイジェスト（`bucketizeAlerts`の5区分: 期限超過／1ヶ月以内／1〜3ヶ月／3〜6ヶ月／6ヶ月超）は数日〜数ヶ月単位の定期確認を前提にした設計であり、3日という期限にはそぐわないため（設計判断の背景は`docs/DESIGN_kobutsu-core.md`に記載する。新規ADRとして記録することを推奨） |

- 古物市場主・古物競りあっせん業の許可
- インターネット取引に関するURL届出の要否判定・届出書生成の自動化
- 複数警察署・複数都道府県の様式差異への対応
- コア抽出における3つ目以降の許可種別への対応（本フェーズは「建設業許可＋
  古物商許可の2例」でコアの汎用性を検証することが目的であり、3例目以降の
  さらなる一般化は次フェーズで改めて検討する）

## 8. 古物営業法上の主な要件（e-Gov法令検索の原文で確認済み・2026年9月）

**この章は、2026年9月に [e-Gov法令検索「古物営業法」](https://laws.e-gov.go.jp/law/324AC0000000108)
の本文（令和7年6月1日施行の現行版。Law RevisionID:
324AC0000000108_20250601_504AC0000000068）を直接確認した結果に基づく。
旧版（第0.1版）で「調査で確認できた範囲」としていた二次情報の記載を
一次資料に基づき訂正・確定した。ただし法令は改正されうるため、
実装着手時点で再度最新版を確認すること。**

### 8.1 許可の基準（欠格事由。第4条）— 確定（一次資料確認済み）

第4条は次の十一号からなる（号の区切り・文言は原文どおり）。

- **第一号**: 破産手続開始の決定を受けて復権を得ない者
- **第二号**: 拘禁刑以上の刑に処せられ、又は第三十一条に規定する罪若しくは
  刑法第二百三十五条・第二百四十七条・第二百五十四条若しくは
  第二百五十六条第二項に規定する罪を犯して罰金の刑に処せられ、
  その執行を終わり、又は執行を受けることのなくなった日から起算して
  五年を経過しない者
  ⚠ **訂正**: 旧版は「禁錮以上の刑」としていたが誤り。刑法等の一部改正
  （令和4年法律第68号）の施行（令和7年6月1日）により「拘禁刑」に
  統合されている。**実装では「拘禁刑」を用いること**
- **第三号**: 集団的に、又は常習的に暴力的不法行為その他の罪に当たる
  違法な行為で国家公安委員会規則で定めるものを行うおそれがあると
  認めるに足りる相当な理由がある者
- **第四号**: 暴力団員による不当な行為の防止等に関する法律第十二条
  若しくは第十二条の六の規定による命令又は同法第十二条の四第二項の
  規定による指示を受けた者であって、当該命令又は指示を受けた日から
  起算して三年を経過しないもの
- **第五号**: 住居の定まらない者
- **第六号**: 第二十四条第一項の規定によりその古物営業の許可を取り消され、
  当該取消しの日から起算して五年を経過しない者（許可を取り消された者が
  法人である場合の役員に関する付随規定があるが、本開発は個人申請のみ
  対象のため実装上は考慮不要）
- **第七号**（⚠ **旧版で完全に欠落していた号。追加必須**）:
  第二十四条第一項の規定による許可の取消しに係る聴聞の期日及び場所が
  公示された日から当該取消しをする日又は当該取消しをしないことを
  決定する日までの間に、許可証の返納をした者（その古物営業の廃止に
  ついて相当な理由がある者を除く）で、当該返納の日から起算して
  五年を経過しないもの。**要するに「取消し処分を免れるために自主返納した
  者」も第六号の取消し歴と同様に5年間欠格になる、第六号とは別の独立した
  号である**
- **第八号**: 心身の故障により古物商又は古物市場主の業務を適正に実施する
  ことができない者として国家公安委員会規則で定めるもの
- **第九号**: 営業に関し成年者と同一の行為能力を有しない未成年者。
  ⚠ **訂正**: 旧版は例外規定を「法定代理人の許可等」という一般的な
  表現で説明していたが、これは不正確。条文上の例外は
  **「その者が古物商又は古物市場主の相続人であって、その法定代理人が
  前各号（一号〜八号）及び第十一号のいずれにも該当しない場合」**という、
  古物商・古物市場主の死亡に伴う事業相続のケースに限定した、狭い例外
  である。「未成年者が親の同意を得れば良い」という一般的な話ではない
- **第十号**: 営業所又は古物市場ごとに第十三条第一項の管理者を選任すると
  認められないことについて相当な理由がある者。実装方針: これは
  「将来的に管理者を選任できる見込みがない」という行政庁側の裁量的な
  判断であり、はい/いいえの単純な入力項目として表現しにくい。本開発では
  FR-K1.3・`checkKobutsuEigyosho`（営業所ごとに実際に管理者が選任されて
  いるかの確認）で実務上カバーされるものとし、`KobutsuKekkakuInput`に
  対応するフィールドは設けない（設計書4.3節に明記する）
- **第十一号**: 法人で、その役員のうちに第一号から第八号までのいずれかに
  該当する者があるもの。**2026年9月実装済み**。`KobutsuKekkakuInput`
  自体は個人申請者本人の判定に専念させ、役員一覧は別型
  `KobutsuOfficerInput[]`（`KobutsuApplicantProfile.officers`）として
  `checkKobutsuKekkaku`の第二引数で渡す設計とした（法人申請の書類生成
  フル対応は引き続き4.6節スコープ外）

### 8.2 管理者（第13条）— 確定（一次資料確認済み）

第13条は以下の4項からなる。

1. 古物商又は古物市場主は、営業所又は古物市場ごとに、当該営業所又は
   古物市場に係る業務を適正に実施するための責任者として、管理者一人を
   選任しなければならない
2. 次の各号のいずれかに該当する者は、管理者となることができない:
   一号 未成年者／二号 第四条第一号から**第七号まで**（8.1節の訂正後の
   号立てに対応。第七号の自主返納者も管理者欠格に含まれる点に注意）
   のいずれかに該当する者／三号 心身の故障により管理者の業務を適正に
   実施することができない者として国家公安委員会規則で定めるもの
3. 古物商又は古物市場主は、管理者に、取り扱う古物が不正品であるかどうかを
   判断するために必要な知識・技術・経験を得させるよう努めなければ
   ならない（努力義務）
4. 公安委員会は、管理者の職務違反等について、解任を勧告できる

⚠ **重要な訂正**: 旧版が挙げていた「管理者は原則として常勤であること」
という要件は、**第13条の条文本文には一切記載がない**。これは施行規則
（国家公安委員会規則）または都道府県警察の実務運用・解釈通達に由来する
可能性が高いが、2026年9月時点では一次資料での裏付けを取れていない。
`KobutsuEigyoshoInput.isManagerFullTime`（設計書4.3節）を実装する場合は、
「常勤性」を欠格事由や必須要件としてではなく、FR-K1.2と同様に
**「機械的に判定しきれない項目として人手確認を促す警告」**の位置づけに
留めること（設計書のeigyosho.js実装は既にこの方針で書かれており、
この点は変更不要）。施行規則の該当条項が判明次第、この節を更新すること。

### 8.3 許可申請の記載事項・添付書類（第5条）

第5条第1項各号により、氏名・名称・住所、営業所・古物市場の名称・所在地、
取り扱う古物の区分、管理者の氏名・住所、行商をしようとする者であるかの別、
インターネットを利用する場合はその旨・識別符号等の記載が求められる。
添付書類は「国家公安委員会規則で定める書類」とされ、具体的な種類は
施行規則に委任されている（**施行規則の該当条項を要確認**）。

### 8.4 許可後の主な届出

- 書換申請: 許可証の記載事項（氏名・住所等）に変更があった場合、
  変更後14日以内（法人の役員変更等は20日以内とする情報もあり、要確認）
- 変更届出: 許可証記載事項以外の変更（取り扱う古物の区分の追加等）は、
  事由発生から3日以内
- 廃業等届出・許可証の返納: 廃業した場合、10日以内に許可証を返納

### 8.5 標準処理期間・手数料（参考。要件判定エンジンの対象外）

- 標準処理期間: 目安40日（行政庁の休日を除く）
- 許可申請手数料: 19,000円
